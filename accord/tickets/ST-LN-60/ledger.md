# Ledger

## Rulings
- Ruling: a fix made for a pull request comment after verify takes the path `failure.md` already gives a failure reported after verify (a review round on the fix, then verify again), not a new path — `gate done` already fails on a commit that changes code after the verified commit (packages/core/src/gate/done.ts:218-245), so a second route would only duplicate it — cost if wrong: the owner wanted a lighter path for small comments; shown at approval
- Ruling: a lane S ticket's pull request is covered too, through the lane S branch `failure.md` already has (continue at the lane S steps; the fix gets another review round) — lane-s.md step 6 opens a pull request that waits for the owner's merge, so it can receive comments like a lane M one — cost if wrong: one sentence of scope the owner did not want
- Ruling: a question about an unclear comment goes to its author as a drafted reply in that comment's thread, under D-04's draft-then-yes, and no comment is fixed until every unclear one is answered — the comments may be related, as the queued intent says, and D-04 already covers every post to GitHub — cost if wrong: the owner wanted such questions asked to them in chat instead
