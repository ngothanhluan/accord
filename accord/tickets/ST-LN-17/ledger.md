# Ledger

## Rulings
- Ruling: the plan critique loop takes the same cap (five rounds) and the same stop from round 3 as review — the owner already put the cap and the non-falling stop on plan-review.md (2026-10-17 queue text), and one rule is one thing to learn — cost if wrong: plan loops stop two rounds later than GSD's cap of 3
- Ruling: rounds are read from review.md alone; "written as its round ended" describes the fixture, not a git-history check — D-05 says the CLI reads the record, and the GSD study says counts come from the round record — cost if wrong: a round written late is counted
- Ruling: a return from verify is a marker the review skill writes into review.md — counts come from the round record, never from frontmatter or git — cost if wrong: a skill that forgets the marker restarts no cap
- Ruling: "a tier once raised stays raised" is a sticky flag set by the first recorded round at or past escalation.fix_round_tier_up in the ticket, not a running total across verify cycles — D-01 says "once raised, stays raised" — cost if wrong: a ticket with three short review passes never tiers up
- Ruling: the count that must fall counts findings of every severity, Nice included — counting only Should and Must would make D-07's second condition never fire on its own, since a Should already stops — cost if wrong: a loop that only trades Nice findings stops early
- Ruling: the cap is five rounds in lane M, lane S and plan critique alike — lane S already caps at five and the earlier Ruling gives plan critique the same — cost if wrong: one lane wanted a different cap
- Ruling: an owner Ruling allowing more rounds names how many, and accord refuses again after that many — an open-ended allowance is the past-the-cap run the benchmark flagged — cost if wrong: the owner is asked again sooner than wanted
- Ruling: the stop prints the ticket's whole Approach section rather than extracting the rejected or reserve options — no marker exists to extract by, and printing about fifteen lines misses nothing — cost if wrong: a longer stop message
- Ruling: an owner acceptance is one line, verdict: accepted-by-owner followed by the owner's sentence in quotes, in review.md and plan-review.md alike, as lane S records it today — cost if wrong: a second form must be read
- Ruling: an owner Ruling allowing more rounds only lets more rounds run; gate done passes only on an acceptance verdict or a later converged round — otherwise the Ruling would skip review — cost if wrong: none found
- Ruling: the hook checks the model for the latest recorded round, whose findings the fix executor fixes, and treats any executor dispatch while the ticket is at the review stage as a fix — the review skill dispatches fixes after recording the round, and build executors run at the build stage — cost if wrong: an executor dispatched at review for another reason needs the tiered model too
- Ruling: approach critique round 1 found two Musts (no fix model in a stop state; no allowance form that lifts a stop under the cap) that are omissions of the chosen option, not of its direction, and the anchor option shares the same core — so the option is amended rather than ruled out, and the critic runs again on the amended text — cost if wrong: one more critique round
- Ruling: the fix executor's model is computed for the latest recorded round, as its own result beside next, stop and refused — the hook and the stop message both need it — cost if wrong: none found
- Ruling: an owner allowance is a ledger Ruling naming the review cycle it applies to, lifts a stop as well as the cap, and counts only in that cycle — D-07 lets the owner allow more rounds at a stop, D-01 restarts the cap per cycle — cost if wrong: the owner is asked again after a verify return
- Ruling: a line whose first word after a list marker or number is Must, Should or Nice and that does not match the finding grammar is unreadable and fails closed; any other line in a round is prose — a skipped Should would fail open — cost if wrong: an odd old spelling is refused
- Ruling: review records merged before this ships keep passing gate done; a session cannot escape the new rules by leaving a marker out — CI runs gate done on old tickets a sweep pull request touches — cost if wrong: an old ticket is rechecked under the new rules
- Ruling: lane S stops print no Approach, which lane S does not have, and offer the lift to lane M as the change of course — cost if wrong: none found
- Ruling: a stop holds from the round that met its condition until an acceptance verdict, or a later no-findings round after an allowance — AC-3 says "a later round reports no findings" — cost if wrong: none found
- Ruling: gate done also fails when a cycle holds more rounds than five plus its allowances, so the cap holds in Cursor and Codex too, not only where accord round is asked — the owner wants rules enforced by tools — cost if wrong: one more gate rule
- Ruling: an executor model given as a full claude-* id is tiered by the family it names; inherit cannot be tiered and accord refuses with the config change to make — fail closed — cost if wrong: an inherit executor must set an alias to reach review round 4
- Ruling: in plan-review.md a `## Closed` resets counting without condition, as AC-4 reads, but a `## Closed` written while a stop holds makes the record unreadable, so the loop cannot be closed past a stop — critique round 2 showed the conditional reset broke a re-plan — cost if wrong: none found
- Ruling: the skills write `## Round <n>` with every finding `open`, and commit it, before any fix executor is dispatched, then update each state to `fixed in <sha>` — the hook and accord round read the latest recorded round — cost if wrong: one more commit per round
- Ruling: a `## Return from verify` marker is accepted only when the stage logic puts the ticket back at review after verify (the fact `Review base:` comes from), and is refused while a stop holds in the cycle before it unless that cycle ends `verdict: accepted-by-owner`; gate done checks every cycle — a stop must reach the owner, and Ruling 2 keeps counting on review.md — cost if wrong: none found
- Ruling: an owner allowance reads `Ruling: the owner allows <n> more review rounds after round <r> of cycle <k> — "<owner's sentence>" — <cost>` (or `plan critique rounds`) and allows exactly n rounds after round r, no more — AC-2 says exactly that many — cost if wrong: none found
- Ruling: the hook skips executor dispatches while accord/tickets/<id>/debug.md is open (its last `## ` heading is not `## Resolved`); accord-debug's dispatches are not review fixes — cost if wrong: a debug fix runs on the untiered model
- Ruling: at the plan critique cap accord prints the stop, as AC-4 says, not a refusal — cost if wrong: none found
- Ruling: a finding line is found by its head after stripping list markers, numbering, emphasis and punctuation, matching Must, Should or Nice in any case; a round with no findings is a line that begins `No findings` — critique round 2 found emphasis and `1)` spellings read as prose — cost if wrong: a prose line that begins with a severity word is read as a finding
- Ruling: the rendered skill copies and the settings.json hook entry in this repository land with the pull request that pins a release holding `accord round` and the `pre-tool-use` event, as ST-LN-64 did — the pinned 0.3.0 has neither and would block every review — cost if wrong: the repository's own sessions run the old review rules until the pin
- Ruling: scripts/compliance.mjs counts a cycle past its cap as allowed when an allowance Ruling in the new form covers it — otherwise the success measure reports a legal allowance as a breach — cost if wrong: none found
- Ruling: records merged or in flight when this ships keep the old rules: a review.md or plan-review.md without the record version line the new skill writes follows the old rules only when its first round predates the commit that pins the release; a later record without the line is unreadable — a session cannot escape by leaving the line out — cost if wrong: an in-flight ticket gets the new rules
- Ruling: the hook denies only when the computed model's family differs from the dispatched one, and a dispatch with no model passes when the computed model is the configured one, since the agent file already carries it — cost if wrong: none found
- Ruling: the hook's catch includes preflight, following the prompt-expansion pattern, so a config typo or pin mismatch never blocks an agent dispatch — cost if wrong: none found
- Ruling: the second audit's splits are settled by the Rulings above, not by more AC rewording: the tier is a sticky flag (Ruling 4), the marker is `## Return from verify` (Ruling 3, 23), the count sums all severities (Ruling 5), the acceptance is one line (Ruling 9), an allowance counts only for the round and cycle it names (Ruling 24), a stop clears only by acceptance or a no-findings round after an allowance (Ruling 10, 18), the stop exits 1, plan critique takes the same allowance form, rounds are counted by section position after the marker or the last `## Closed`, and the hook judges executor dispatches at review outside an open debug.md (Ruling 11, 25) — each audit pass found new wording splits the Rulings already fix — cost if wrong: a planner reads an AC without its Ruling
- Ruling: an allowance or acceptance counts only when it carries the owner's sentence in quotes; accord cannot prove who wrote a line, as with `verdict: accepted-by-owner` today, so the review and approval commits remain the check — cost if wrong: an agent that writes a false owner quote lifts a cap
- Ruling: a `## Return from verify` marker names the commit verification.md recorded when the ticket left verify (`## Return from verify <sha>`), and accord accepts it when that commit is an ancestor of HEAD at which verification.md held that sha — a fact that survives the cycle and a CI sweep, where the stage fact does not (approach critique round 3) — cost if wrong: the loader needs one more git fact
- Ruling: in plan-review.md a stop lifts on an acceptance verdict anywhere after the stop round in its segment, so the `## Closed` the plan skill appends after acceptance stays readable — cost if wrong: none found
- Ruling: the legacy rule is record-local: a review.md or plan-review.md without the record version line follows the old rules only when the ticket is done on the default branch; for a ticket in flight at release, accord round prints the refusal with the one-line fix (add the version line) and the old rounds count as cycle 1 — Rulings 2 and 3 keep git out of counting — cost if wrong: an in-flight ticket meets the new rules mid-review; replaces the earlier commit-order legacy Ruling
- Ruling: a lane S ticket sent back to review by a hand-made commit after its verdict starts a new cycle with the same marker, naming the commit that held the verdict — lane S has no verify, but the same reopen path exists — cost if wrong: none found
- Ruling: accord round prints the model as the family alias (haiku, sonnet, opus), the only values the agent tool takes, and the hook compares families — cost if wrong: a pinned full model id is not passed through on tiered rounds
- Ruling: fixModel is computed from round headings and the tier rule alone, never from finding lines, so an unreadable finding line cannot make the hook fail open — cost if wrong: none found
- Ruling: Ruling 5 (the count sums every severity) no longer applies, since D-09 drops the count rule — cost if wrong: none found
