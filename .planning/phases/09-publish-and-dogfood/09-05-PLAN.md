<objective>
Bootstrap the registry so that `0.1.0` can be published from Actions over OIDC, and prove the scope
is ours before anything else in this phase assumes it.

D-151: publish `0.0.0` by hand with a granular token so the package exists on npmjs.com, configure
the trusted publisher there against this repository and the fixed workflow filename, then let
`0.1.0` publish from Actions over OIDC. npm configures trusted publishing on a package page, so the
package has to exist first; this is the only ordering under which ROADMAP criterion 1 — *published
from GitHub Actions via npm trusted publishing* — is literally true of `0.1.0` itself.

The cost is one permanent `0.0.0` row on npm that nothing installs, because no `config.yml` ever
pins it. That row is deliberate and is not a mistake to clean up later.

Purpose: two things in this plan cannot be done by an agent, and both are load-bearing. Scope
ownership of `@accord-dev` is **unverified** — `npm view` returns 404 for both package names, which
proves the *names* are free and says nothing about *scope* ownership, and `npmjs.com/org/accord-dev`
returned a bot-block that must not be read either way. Everything downstream already names the
scope. And the bootstrap itself is an authenticated action on an external service.

Output: a package on the registry at `0.0.0`, a trusted-publisher record, a revoked token, and
`09-VERIFICATION.md` created with the first three evidence sections.
</objective>

  <name>Task 1: Confirm the npm scope `@accord-dev` is ours</name>
  <what-built>
    Nothing yet. This is a precondition check that must clear before any publish.

    What is already known, and what it does not prove: `npm view @accord-dev/accord` and
    `npm view @accord-dev/accord-core` both returned `npm error code E404` on 2026-09-20. That
    proves the two *package names* are free. It does **not** prove the *scope* is claimable — an npm
    scope can be registered with no packages in it. `https://www.npmjs.com/org/accord-dev` returned
    HTTP 403, which is a bot-block and is not a signal about existence in either direction.

    Why this cannot wait: the scope name is already written into `packages/cli/package.json`,
    `packages/cli/src/pin.ts:16`, the `config.yml` that `accord init` generates, 17 committed
    goldens, and the `npx` invocation inside every emitted `accord.yml`. If the scope is taken, all
    of that moves — and it is far cheaper to discover now than after `0.0.0` is on the registry.
  </what-built>
  <how-to-verify>
    Signed in to npmjs.com as the account that will own the package:

    1. Open `https://www.npmjs.com/settings/<your-username>/packages` and check whether an
       organisation named `accord-dev` is already listed under your account.
    2. If it is not, go to your avatar menu -> **Add an Organization** and attempt to create
       `accord-dev`. The free tier is sufficient for a public scoped package.
    3. Record which of these three happened:
       - **Created it just now** — note the date.
       - **Already owned it** — note that.
       - **Taken by someone else** — stop. Do not proceed to Task 2. This is a phase-blocking
         finding: every string naming `@accord-dev` has to change, which is a re-plan of 09-01,
         09-04 and the 17 goldens, not a fix inside this plan.
    4. Confirm the local npm client is authenticated as that account: `npm whoami` prints the

<task type="checkpoint:human-action" gate="blocking-human">
  <name>Task 3: Publish `0.0.0`, configure the trusted publisher, revoke the token</name>
  <precondition>09-01 is committed: `packages/cli/package.json` declares exactly one runtime dependency and `packages/core/package.json` is `private: true`. Publishing before that change puts a manifest on the registry that 404s on every install, and it cannot be replaced.</precondition>
  <action>Publish `0.0.0` by hand with a granular token, configure the npm trusted publisher against this repository and `publish.yml`, then revoke the token.</action>
  <instructions>
    Three actions on npmjs.com, in this order. None can be done by an agent: the first needs an
    authenticated npm session, the second is a web form on a page that does not exist until the
    first completes, and the third is registry-side credential state.

    **Before starting**, confirm the precondition from this repository:
    `node -p "Object.keys(require('./packages/cli/package.json').dependencies)"` prints
    `[ 'commander' ]`. If it prints two names, stop — 09-01 has not landed, and publishing now
    produces a `0.0.0` that 404s on install and can never be replaced.

    **1. Publish `0.0.0`.**
    - Create a **granular** access token on npmjs.com scoped as narrowly as the UI allows
      (read and write on the `@accord-dev` scope; no organisation management). A classic
      automation token also works but grants more.
    - Temporarily set `packages/cli/package.json`'s `version` to `0.0.0`. Do **not** commit this
      change — it is a local, throwaway edit, and the repository's version of record stays `0.1.0`.
    - `npm publish --workspace packages/cli --access public`.
    - Restore the manifest to `0.1.0` and confirm `git status --porcelain packages/cli/package.json`
      prints nothing.

    **2. Configure the trusted publisher.**
    On `npmjs.com` -> package `@accord-dev/accord` -> **Settings** -> **Trusted Publisher**, add a
    GitHub Actions publisher with:
    - Organization or user: the GitHub owner of this repository
    - Repository: this repository's name
    - Workflow filename: `publish.yml` — **filename only, including the extension**, matching
      `.github/workflows/publish.yml` exactly, with no path and no extra whitespace
    - Environment name: **leave blank**. It is optional, and an environment whose branch protections
      do not allow a tag ref blocks the job with an error that reads nothing like its cause.

    **3. Revoke the bootstrap token.**
    Delete the granular token on npmjs.com -> Access Tokens. Note the date. From this point the
    repository holds no long-lived registry credential, which is the property OIDC exists to give.

    Capture as you go, because Task 4 needs it: the `npm publish` output, the four trusted-publisher
    field values exactly as typed, and the revocation date.
  </instructions>
  <verification>`npm view @accord-dev/accord version` returns `0.0.0`; `npm token list` no longer shows the bootstrap token; `git status --porcelain packages/cli/package.json` prints nothing.</verification>
  <why-human>
    An authenticated action on an external service, a web form, and a credential revocation. No CLI
    the agent may run performs any of the three, and the project's standing constraint is that
    accord never holds an API key.
  </why-human>
  <resume-signal>Paste the `npm publish` output, the four trusted-publisher field values, and the token revocation date.</resume-signal>
</task>
