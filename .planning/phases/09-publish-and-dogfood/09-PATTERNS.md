## Pattern Assignments

### `.github/workflows/publish.yml` (config, event-driven)

**Analog:** `.github/workflows/ci.yml` lines 1-27.

**Step shape to copy verbatim** (`ci.yml:17-27`, the `check` job):
```yaml
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: ${{ matrix.node }}
          cache: npm
      - run: npm ci
      - run: npm run build
```
Publish job: same actions at the same major (`@v7`), `node-version: 24`, `cache: npm`, then `npm ci` and `npm run check` as ONE step (D-152) instead of the four separate script steps — `check` is `build && lint && typecheck && test` (`package.json:11`) and its `build` already sequences core before cli (`package.json:9`), which D-150's bundling depends on.

**Multi-line `run:` shape to copy** (`ci.yml:41-45`, the `examples` job):
```yaml
      - name: lint and gate each example through the real CLI
        shell: bash
        run: |
          # Deliberately not -e: both examples are reported on one run, so a failure in the first
          # does not hide the state of the second.
          set -uo pipefail
```
House style: an explicit `shell: bash`, a lowercase descriptive `name:`, and a comment above any non-obvious `set` line explaining the flag choice. Copy that; the publish steps use `set -euo pipefail` (fail fast is correct there) and the smoke retry uses `set -uo pipefail`.

**Permissions:** `ci.yml:6` declares `permissions: { contents: read }` at WORKFLOW level. In `publish.yml` declare `id-token: write` at JOB level only, so the `smoke` job does not inherit it.

**Most likely to be got wrong:** the filename. The npm trusted-publisher record matches on filename; renaming `publish.yml` later silently breaks auth. Fix it at creation. Second most likely: `GITHUB_ENV` does not cross a job boundary — the smoke job needs `needs.publish.outputs.version`, which requires an `id:` on the tag-check step plus writes to `$GITHUB_OUTPUT`.

**Analog:** `packages/core/scripts/gen-templates.mjs` — whole file, 16 lines. Copy its shape exactly:

```js

import { mkdirSync, readdirSync, readFileSync, writeFileSync } from 'node:fs';
import { fileURLToPath } from 'node:url';

const root = fileURLToPath(new URL('../', import.meta.url));
const dir = `${root}templates/`;
...
    const text = readFileSync(dir + f, 'utf8').replace(/^﻿/, '').replace(/\r\n/g, '\n');
...
writeFileSync(`${root}src/generated/templates.ts`, `// Generated by scripts/gen-templates.mjs from templates/*. Do not edit.\n...`, 'utf8');
```

Four things this carries that the new script must too:
1. **First-line comment** naming the source, the output, the decision id, and why Node built-ins are legal here (outside `src/`, where the eslint core-purity rule bites — core-only, but keep the comment for consistency).
2. **`fileURLToPath(new URL('../', import.meta.url))`** for the root — never `__dirname` (ESM) and never `process.cwd()`. For `packages/cli/scripts/gen-readme.mjs` this resolves to `packages/cli/`; the root README is `${root}../../README.md`.
3. **`.replace(/^﻿/, '').replace(/\r\n/g, '\n')`** — strip BOM, normalise to LF. Non-negotiable: the drift test compares byte-for-byte and CI runs on Windows.
4. **`console.log('generated ...')`** one-line receipt.

**Wiring:** `package.json:8` — `"gen": "node packages/core/scripts/gen-templates.mjs && node packages/core/scripts/gen-skills.mjs"`. Append ` && node packages/cli/scripts/gen-readme.mjs`.

**Most likely to be got wrong:** the output is `packages/cli/README.md`, a plain `.md`, not a `.ts` record — so unlike the two analogs there is no `JSON.stringify` and no `as const` export, and the "Do not edit" banner has to be a Markdown comment (`<!-- Generated by ... Do not edit. -->`) or the npm page renders it. Second: the root README's repo-relative links (`docs/design.md`) 404 on npmjs.com — the generator either rewrites them to absolute GitHub URLs or the ticket rules they are acceptable. That is a D-156 scope decision, not the generator's to invent.

### Drift test for `packages/cli/README.md` (test, file-I/O)

**Analog:** `packages/core/test/templates.test.ts`, `describe('generated module')`.

**Drift case:**
```js
  it('generated module matches templates/ (drift)', () => {
    const onDisk = readdirSync(templatesDir).filter((f) => /\.(md|html)$/.test(f)).sort();
    expect(Object.keys(templates), 'template file set drifted: run npm run gen').toEqual(onDisk);
    for (const name of onDisk) {
      const text = normalise(readFileSync(templatesDir + name, 'utf8'));
      expect(templates[name as TemplateName], `${name} drifted: run npm run gen`).toBe(text);
    }
  });
```

**LF/BOM case, also copy:**
```js
  it('LF and no BOM on disk', () => {
    for (const name of names) {
      const raw = readFileSync(templatesDir + name, 'utf8');
      expect(raw, `${name} has CR`).not.toContain('\r');
      expect(raw.startsWith(BOM), `${name} has BOM`).toBe(false);
    }
  });
```
with `const BOM = String.fromCharCode(0xfeff);` and
`const normalise = (text) => (text.startsWith(BOM) ? text.slice(1) : text).replace(/\r\n/g, '\n');` (lines 11, 20-21).

The house signature is the **assertion message carrying the fix command**: `` `${name} drifted: run npm run gen` ``. Reproduce it.

**Most likely to be got wrong:** comparing raw bytes of the root README against raw bytes of `packages/cli/README.md` on a Windows checkout. The test must `normalise()` the *input* it re-derives and compare against the on-disk generated file read as-is, exactly as the analog does — otherwise `.gitattributes` CRLF behaviour makes it red on `windows-latest` only.

## Shared Patterns

### Comment voice
**Source:** every file read for this map.
**Apply to:** all new workflow YAML, generator scripts, and tests.
The house style is a comment that names the *failure mode a line prevents*, not what the line does. `ci.yml:42` (`"Deliberately not -e: ... a failure in the first does not hide the state of the second"`), `workflow.ts` (`"Keep this. ... the job would report green having gated nothing"`), `scaffold.test.ts:230` (`"a gate that silently passes is worse than no gate"`). Decision ids (`D-150`, `T-07-14`, `A-24`) are cited inline. Reproduce this; a plain descriptive comment reads as foreign here.

### Exact string equality on versions
**Source:** `packages/cli/src/pin.ts:14-17`.
**Apply to:** publish.yml's tag-vs-manifest check.
```ts
export function pinMessage(pinned: string | undefined, running: string): string | undefined {
  if (pinned === undefined || pinned === running) return undefined;
  return `config.yml pins accord ${pinned}, running ${running} - run: npx --yes ${pkg.name}@${pinned}`;
}
```
No semver, no range, no tolerance. The workflow check uses `node -p "require('./packages/cli/package.json').version"` and shell `!=`, with `${TAG#v}` as the only transformation.

### Generated-and-committed file
**Source:** `packages/core/scripts/gen-*.mjs` + the `generated module` describe block.
**Apply to:** `packages/cli/README.md`.
Three parts, always together: a `scripts/gen-*.mjs` outside `src/`, wired into the root `gen` script; the committed artifact with a "Do not edit" banner naming its generator; a drift test whose assertion message is `run npm run gen`. `.gitignore` lists `dist/` but not `README.md`, so committing the artifact is fine.

### Posix paths
**Source:** `packages/core/scripts/gen-skills.mjs:13` — `.split(sep).join('/')`, commented *"Keys are posix ... the same native-to-posix conversion packages/cli/src/load/fs.ts makes for a reported path (D-51)."*
**Apply to:** anything this phase writes or prints that carries a path.
