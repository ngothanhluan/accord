# ST-LN-44 per-test action table

There is one row per test in measurements.md, with the same # numbers (113 rows). The owner approves this table once, at the approach (D-05), and build carries it out. This ticket changes no product code (D-11), and no script code either: every cut below is on the test side.

**Actions**
- **faster**: the same test, with the same title, made cheaper.
- **moved**: split or relocated. The destinations column lists every destination as `file :: exact title`, including the one that keeps the original title.
- **merged**: into the named test. None.
- **removed**: needs the owner's yes. None proposed.
- **kept**: with the reason the test cannot get under 10 s in a full run, where the loaded time is 1.7-5x the alone time. A kept row takes every cut listed in its "how" column. It also carries a ceiling: the larger of its two full-run times today, rounded up.
- **unchanged**: already under 10 s in both full runs, so nothing is done. This is not an exception: the test must stay under 10 s.

**Rules the owner approves with this table**
1. **Criterion tests.**
   - A criterion test is never split and never moved to core. Its action is faster or kept. The one exception is ST-LN-19 ac-1, which follows D-08.
   - A criterion test whose scenario names a command stays at the CLI layer. Only its setup (the Given) may be built without the CLI. Any CLI exit or output check that drops out of it is made by another CLI test, named in the row (ac-4).
   - No risk assertion is moved into a criterion test.
2. **The faster/kept line.** This covers criterion tests that were over 10 s in either full run, and risk tests that a guard keeps whole.
   - The test is kept when no cut is left for it.
   - The test is also kept when the architects' estimate after its listed cuts is over 4 s alone. In worktree.test.ts that means over 80 git spawns, at that report's ~50 ms per spawn. Where no estimate was given, today's alone time is used, since the cuts only lower it.
   - Otherwise the test is faster. #1 is the exception, because D-08 fixes its cut.
   - Every other risk test is split until each destination is under 80 spawns. Where a destination stays over 80, the row says why it cannot be split further.
3. **Measuring run and the owner's list.** After build, the full run before review is the measuring run. A faster or moved row (or any of its destinations) still over 10 s there goes back to the owner as one list before verify, each with its time and a proposed further split or keep. Nothing becomes kept without the owner's yes, which is written into the ticket as a Decision. The same list also takes:
   - a kept row over its ceiling;
   - an unchanged row over 10 s;
   - any row at all over 7 s, whatever its action, as a margin. That includes unchanged rows and kept rows under their ceiling.

   No other cut is added at build without the owner.

   **Late keeps.** When the owner says yes to a late keep, that row in table.md changes to kept, with its reason and its ceiling. The change alters the table's sha256. So the Decision that records the table's hash is updated, and the ticket is re-approved (`accord approve`) before verify.
4. **Assertions.** Every row whose test body changes maps each old assertion to its new place in the note column, kept rows with cuts included. A kept criterion test takes only cuts that leave its assertions untouched. Any cut the reports proposed that would change an assertion of a kept test is listed as not taken.
5. **Data-deletion guards.**
   - A clone template never contains a linked worktree. Any `worktree add` happens after the copy, in the copy. The copy-vs-built risk test also compares `git worktree list --porcelain`.
   - The origin check applies only to templates that have a remote:
     - the `makeClone` template (worktree, hook, bin and after-verify tests);
     - the drop templates (the claimed clone and the crlf claimed clone);
     - the upgrade templates (clone, other clone and remote).
   - The lane-s, show and dashboard templates, and every lane-repo template, have no remote and are excluded. No origin is ever added to a template to satisfy the rule.
   - For each of these templates, the copy routine asserts four things:
     - `git remote get-url origin` equals the copy's own remote;
     - `git remote get-url --push origin` equals the copy's own remote;
     - the fetch URL differs from the template's own remote URL;
     - the push URL differs from the template's own remote URL.
   - Tests that judge several branches in one clean stay multi-branch, and a split never separates branches that one clean judges:
     - #5's first destination (ST-9, ST-10 and ST-11, with the toEqual at worktree.test.ts:2188-2193);
     - #5's block f (ST-12 and ST-13);
     - #50, which stays whole;
     - #92, which stays whole: the 4-branch clean at :1527;
     - #93, which stays whole: one clean at :1505 judges ST-9, ST-10 and ST-11;
     - #56 and #72.
   - #105 keeps one real `accord drop` followed by `accord worktree clean`, so ST-LN-34 ac-3 still runs end to end.
6. **Test-helper guard (H8).** `run()` in packages/cli/test/helpers/repo.ts (:91-99) gets the same temp-folder guard that `gitIn` has (:18-25). A template copy with an unset path can then never run accord in the real checkout. The guard must accept a cwd that exists only under the temp folder (for example `${sib}/sub`), and it must refuse the checkout.
7. **New titles** start with `risk:`, because `core/src/lint/tests.ts` flags any case id that has no `risk:`, no `@test:` tag and no baseline entry.

**Levers**
- **H1 template.** `makeClone` copies a per-file template of the remote and the clone, then runs `git remote set-url origin`. That takes it from 11 spawns to 1. The same idea gives `makeLaneRepo` and claim-state templates ("tpl"). Templates are built in `beforeAll` and removed in `afterAll`, and only where two or more tests, or a split, share them.
- **H2.** `otherClone` becomes one `git clone` with its config on the command line, which takes it from 4 spawns to 1.
- **H3.** A step that only sets the test up is done with git or a file write.
- **H4.** Split. Each independent repository block becomes its own `risk:` test.
- **H5.** One `for-each-ref` replaces several ref reads.
- **H6.** No auto-maintenance: `maintenance.auto=false`, `gc.auto=0`, `receive.autogc=false`. The saving is unconfirmed.
- **H7.** Continue without a remote: `git remote remove origin` runs first. It is used only in tests that check holds, whose scenario names no fetch, and which push nothing.
- **H8 run guard.** Rule 6. Listed on every row that uses a template.
- **core-ready hashes.** approved_hash and ac_hash are computed by core and written into the file, in place of the `approve` and `gate ready` runs that only set a test up. The helpers move from dashboard.test.ts and show.test.ts into test/helpers/lane.ts.
- **async runScript.** workflow-script.test.ts gets a promisified `runScript`: a test's sandboxes are built first, then their script runs go through `Promise.all`.

**Expected alone after.** This column holds the architects' estimates.
- Rows outside worktree.test.ts give seconds; "?" means the report gave no number.
- Rows in worktree.test.ts give git spawns, as that report did.
- Nothing was run to produce these numbers.
- The worktree measurements are noisy: the alone run was slower than both full runs for #21 (67.8 s against 21.4 and 30.2), #45 (58.4 against 5.8 and 18.7) and #65 (43.9 against 6.1 and 13.9). These estimates stay unproven until the measuring run (rule 3).
