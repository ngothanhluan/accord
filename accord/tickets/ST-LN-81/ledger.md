# Ledger

## Rulings
- Ruling: the missing-report refusal sits in `accord approve` (lane M), not in `gate ready` — `gate ready` runs at every stage, so it would block every ticket already past approval; approve runs once, before the plan, after the intent scout ran — cost if wrong: a lane S ticket can still skip its scout unseen, to be closed in a follow-up
- Ruling: lane S is not refused for a missing report in this ticket — lane S never runs `accord approve`, and its `## Scope` is already checked against the diff by `gate/scope.ts` — cost if wrong: a skipped lane S scout stays invisible
- Ruling: a report saved before the ticket exists is written by the main session to `accord/tickets/<id>/scout.md` right after `accord new ticket`, and `accord scout check` takes a file path, not an id — the lane scout runs before any id exists (packages/core/skills/accord/SKILL.md:62,71) — cost if wrong: a second save path to add later
- Ruling: the planner reads `scout.md` as its starting list and still runs its own impact search — ST-LN-80 D-03 keeps the planner's search — cost if wrong: the 65% re-read rate drops less than it could
- Ruling: the lane numbers that `accord scout check` prints are information, not a failure; exit 1 is kept for a contradicted claim or an unresolved citation — the owner may override a lane (accord SKILL.md) — cost if wrong: an agent may ignore a lift it was shown
- Ruling: lint does not re-check a saved report's citations as the code moves on — a report is evidence at its commit, like a research record — cost if wrong: an old report cites stale lines, which the planner's own search catches
- Ruling: a logged search runs as a JavaScript regular expression over the files git tracks in the logged folders — build output and ignored files are not the scout's claim, and one dialect keeps Windows and POSIX equal — cost if wrong: a scout that searched with git grep syntax sees a check fail on an escape
- Ruling: every `path:line` in the report text is a citation, and it resolves when git tracks the file and the line is within its length; the check does not judge what the line says — that needs a model — cost if wrong: a right line number with a wrong reading passes
- Ruling: `accord approve` runs the same check on `scout.md` rather than only testing that the file exists — a failing report approved is the trust gap this ticket closes — cost if wrong: an approval blocked by a check bug until it is fixed
- Ruling: the approach ladder is 1. Checked report, facts read on demand: a pure core module judges the scout's fixed reply form against the tracked file list and file reads the command hands it, and both the new check command and approve call it; 2. Scout facts carried on the snapshot: the same core module, but the shared loader reads the tracked list and every lane M report into the snapshot so a core rule judges from it alone; Checked report, facts read on demand is Recommended because it meets all four criteria with no cost to other commands while the judging stays in the pure core — kept so a resumed or revised round critiques the option ## Approach names and nobody picks again — a ruled-out option comes back
- Ruling: the Absent table header is `| Claim | Pattern | Folders | Allowed hits |`; cells split on unescaped `|`, `\|` reads as `|`, one pair of backticks is stripped; folders and allowed hits are separated by commas or spaces and matched as `## Scope` entries are — GFM table rules — cost if wrong: a pattern holding `|` must be escaped
- Ruling: each logged pattern runs as a JavaScript regular expression with no flags, line by line, over the working-tree text of tracked files, and a pattern that does not compile fails its row with exit 1 — matches grep's line model — cost if wrong: a pattern written to span lines never matches
- Ruling: a citation is `path:n`, `path:n-m` or `path:n,k` whose path holds a `/` or a `.` and is not preceded by `://`; it resolves when git tracks the file and every number is between 1 and its line count; every `## Files` entry must be a tracked path — keeps host:port prose out — cost if wrong: a host:port in prose fails the check
- Ruling: a report with no `## Files` section fails with exit 1 — no lane numbers can be computed from it — cost if wrong: a questions-only report cannot be saved as `scout.md`
- Ruling: the generated copies excluded from the count are the files `accord skills sync` writes plus the `generated:` entries, the same list the branch facts use; `sensitive:` entries are read from the working tree's config — lane.md's definition, and the lane scout runs on the default branch — cost if wrong: a copy is counted as an expected file
- Ruling: the approve refusal applies to `lane: M` only, with no exemption for a lane M ticket re-approved after this change; such a ticket needs a report or a `skipped:` line — ac-4 names lane M — cost if wrong: a lane L story skips its scout unseen
- Ruling: lane.md tells the main session to write the checked reply to the new ticket's `scout.md`, commit and push it, before following the `enter:` or `stop:` line, in lanes S and M; intent step 2 saves its own checked reply when no `scout.md` exists — the Intent's "the report is saved in the ticket" — cost if wrong: tickets queued before this change reach approve without a report
- Ruling: the test helpers that build lane M repositories seed a `scout.md` holding a `skipped:` line — one change instead of about 20 test edits — cost if wrong: a test that lists a ticket folder or checks a clean tree changes
