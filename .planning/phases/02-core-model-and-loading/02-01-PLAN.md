<objective>
**As a** developer or BA whose ticket lives in a repository, **I want to** hand core a flat snapshot of that repository and receive typed tickets, scenarios with their Markdown line numbers, and verification records — identically on Windows and Linux, whatever the line endings or BOM — **so that** every later phase (lint, gates, CLI, MCP) works on one deterministic model instead of re-reading files.

Purpose: this is the tracer for Phase 2. One entry point (`loadSnapshot`) is wired through every layer the phase touches — key normalisation, frontmatter split and YAML parse with the D-20 validator, the fence-aware section scanner, EARS line extraction, Gherkin extraction with line remapping, the verification-record parser — over ONE realistic fixture (`valid-build`: an epic, a Vietnamese build-profile story with a Background and two tagged scenarios, its verification record, a `config.yml`, and non-accord files for `tree`). The golden proves ROADMAP criteria 1–4 on the happy path; Plans 02-02 to 02-05 add the error findings for each layer as expansion slices, 02-06 adds the tick write primitive, 02-07 the CLI filesystem loader.

Output: the `RepoSnapshot` model, `loadSnapshot`, the renamed `Finding`, the fixture reader helper, the `valid-build` fixture and its golden, and the D-55 public API.
</objective>
