<assumption_delta_decision>
**Decision: `add-alongside`** — and it is the mechanism of G-1, not a bookkeeping note.

The deterministic detector surfaced two `pluralization` signals, both quoted from the
ROADMAP criteria: "a second run is a no-op" (criterion 2) and "Two techniques render
alongside the roles" (criterion 5). Assessed honestly, **both are `no-change`**: each
describes behaviour shipped and verified in 06-01..06-04 (criteria 2 and 5 are both
`✓ TRUE` in 06-VERIFICATION.md), and this gap round introduces no second case for
either.

The real delta is the one the dispatch invited me to look for, and it is genuine. Up
to 06-04 there was ONE set noun in this command — "the declared directories" — and it
carried three jobs at once: what gets written, what gets link-guarded, and what gets
scanned. 06-05 split the third job onto a second, larger set (`allSkillDirs()`) and
left the guard attached only to the first. The noun lost its monopoly and nothing was
re-derived from the split. That is exactly how an undeclared directory reaches
`statSync` having never passed `assertNoLink`.

So this plan names both sets explicitly and states the disposition of each:

| set | source | guard | disposition on a link |
|-----|--------|-------|-----------------------|
| write set | `skillTargets(config)` | `assertNoLink`, pre-pass at `skills.ts:95` | throw `UsageError`, exit 2, nothing written |
| scan set | `allSkillDirs()` | the new per-component check, Task 1 | skip the directory, exit code unchanged |

Two sets, two dispositions, one reason. The dispositions differ because the write set
is where accord's bytes go (a refusal is the only safe answer) and the scan set is
advisory output that D-113 forbids from changing the exit code.
</assumption_delta_decision>
