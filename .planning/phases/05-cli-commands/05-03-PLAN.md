<objective>
`accord gate ready <id>` and `accord gate done <id>` work end to end, and a passing Ready
performs the one write the whole project makes: `ac_hash` into the ticket file.

Purpose: this is the gate the whole product exists to enforce, reachable from a terminal for the
first time. The write is not optional decoration — `gate.ac-hash-missing` is an error on both
profiles, so `gate done` can never pass unless Ready wrote the hash.

Output: packages/cli/src/commands/gate.ts, its registration in run.ts, and sandbox tests for
both verdicts and all three write outcomes.
</objective>

    - a pass verdict on `gate ready` with an acHash present writes the hash into the ticket file and prints a one-line notice to stderr
    - running the same passing `gate ready` a second time leaves the file bytes unchanged and prints no write notice
    - a fail verdict leaves the file bytes unchanged
    - `gate done` leaves the file bytes unchanged on both verdicts
    - a pass verdict whose acHash is undefined (no tagged scenario) writes nothing
    - when the ticket file cannot be written, stdout still carries the full gate result, stderr names the write failure, and the exit code is 2
  </behavior>
  <action>
Extend packages/cli/src/commands/gate.ts. After the result has been written to `ctx.stdout` —
the ordering is the requirement, not an implementation detail (D-97: the verdict is true and
must be reported even when the write fails) — perform the write when all three hold:
`which === 'ready'`, `result.verdict === 'pass'`, and `result.acHash !== undefined`.

Resolve the file from the loader, not from the argument: take
`ctx.snapshot.tickets[id].file`, which is the repo-relative posix path the loader produced, and
join it to `ctx.root`. Never build the path by concatenating the raw `<id>` argument — that is
the only route by which a crafted id could reach a file outside accord/tickets.

Read the current text, compute `setFrontmatterKey(text, 'ac_hash', result.acHash)`, and write
only when the result differs from the text on disk. The compare is what makes a second
consecutive `gate ready` a no-op on mtime (D-96). On a successful write, print one line to
`ctx.stderr` naming the file and the hash — stderr, so a `--json` consumer's stdout stays a
single clean document (D-98).

When the read or the write throws, wrap it in `UsageError` naming the file and the underlying
message, and throw. The runCli exit map already turns that into stderr plus exit 2, and because
the result was already written to stdout the caller sees both the true verdict and the real
failure. Do not convert the verdict to fail — nothing is wrong with the ticket's content (D-97).
Do not exit 0 with a warning — CI would go green with no hash recorded and the failure would
resurface much later as an unexplained `gate done` failure.

Add no flag, option, or environment variable that enables or suppresses this write (D-96).
  </action>

    <fails_when>non-zero exit, or the vitest summary reports "0 passed" / "No test files found" for the gate filter</fails_when>

  </acceptance_criteria>
