<objective>
Move the version, and close D-157's loop.

npm renders the README as of publish time, so `0.1.0`'s page is stale by design and `0.1.1`'s is
correct. Two benefits fall out of that choice: the tag→OIDC path is proved twice rather than once,
and the bump walks the D-94 pin through a real version change, which is a thing nobody has done to
this codebase before.

Purpose: the bump is the phase's last piece of real work, and it is the one most likely to be got
wrong. The version string lives in far more places than the three `09-CONTEXT.md` names. Counted
against the working tree: 1 manifest + 1 repository config + 2 examples + 18 fixture configs + 17
committed goldens + the generated workflow = **40 files**, and three of those groups fail **in CI on
the release tag**, not locally before the commit. That ordering is what makes them expensive, and it
is why the checklist is in this plan rather than in someone's head.

Output: a swept working tree, a second published version, and the phase's evidence file complete.
</objective>
