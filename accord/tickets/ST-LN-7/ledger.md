# Ledger

## Rulings
- Ruling: Pick up's `claim: <id>` commit is made by `accord worktree open` right after `git worktree add` and before `setup`; the skill pushes it — a fresh branch whose tip equals a commit on `origin/main` would be judged merged by `worktree clean` and credited by `gitClaims` to that commit's author — cost if wrong: a failed setup leaves a claim commit on a branch not yet pushed.
- Ruling: `accord worktree open` prints a distinct first line when the session must stop and another when it took the hold, so the skill never decides by spotting a path in the text — critic finding 16 — cost if wrong: one line of output changes.
- Ruling: fetch `origin` with `credential.interactive=never`, `ssh -o BatchMode=yes` and `GIT_TERMINAL_PROMPT=0`, and judge against `origin/HEAD`'s target, else `origin/main`, else `origin/master`, reusing load/fs.ts:447-454 — the lookup `gitPeopleOnRefs` already uses — cost if wrong: a team whose main remote is not `origin` gets no cleanup, and loses nothing.
- Ruling: a holder is live while a process with its pid and its recorded start time is in the OS process table; `process.kill(pid, 0)` alone is not used — pids are reused — cost if wrong: a reused pid keeps a dead hold until that process ends.
- Ruling: `worktree clean` names a kept worktree only when its ticket merged (dirty, held, or the one it runs in), never an unmerged one — ac-5 and D-11 — cost if wrong: none.
- Ruling: `setup` output is captured and shown only on failure (the command and the end of its stderr) — a clean `npm ci` floods the chat — cost if wrong: a slow setup looks idle.
- Ruling: the sibling path is built from the main worktree's folder (the first entry of `git worktree list`), never the current one's — no `accord-st-9-st-10` names — cost if wrong: none known.
- Ruling: `accord new ticket --worktree` pushes the branch itself, before setup; Pick up keeps the skill push of the first Ruling, and the skill pushes even after a setup failure — @ac-6 maps to one CLI-layer test, which sees only a push the CLI makes — cost if wrong: the two flows push from different places.
- Ruling: the approach's `risk:platform` and `risk:spawn` tests become `risk:parsing` / `risk:complex-branching` and `risk:security`, and `risk:path` is dropped — kinds come from the reviewer's list, and the forward-slash path assertions in the ac tests already catch a backslash on Windows CI — cost if wrong: one test to add back.
- Ruling: the branch is the one `accord status --json` names (`claimBranches`, else `claimTemplate`), and `worktree clean` maps a branch to its ticket through `ticketOfBranch` — the same `branch` the skill already uses — cost if wrong: none with the default `t/{id}`.
- Ruling: `setup` is read from the new worktree's own `accord/config.yml` — for Pick up and New request those are the commands committed on origin/main; for a ticket branch that exists, they are that branch's, as trusted as its code that `tests.affected` runs (plan critique 1.16) — cost if wrong: a setup changed only in the main checkout is not used.
- Ruling: `worktree open` with no branch claims only a ticket present in the main checkout's `accord/tickets`, and checks the id against the ticket schema pattern before building any path — the id becomes part of a folder path — cost if wrong: a ticket only on origin/main cannot be picked up until the main checkout is updated.
- Ruling: `worktree clean` fetches and prints nothing when there is no `origin` remote or no ticket worktree besides the main one — the Veto forbids friction — cost if wrong: none known.
- Ruling: `worktree clean` never removes the main worktree, and drops the hold entry of each worktree it removes — cost if wrong: none known.
- Ruling: the session probe writes only filtered environment variables (names holding TOKEN, KEY, SECRET, PASS, AUTH or CRED left out) and keeps command lines only for `node` rows, with the home folder as `~` — the fixtures go into a public repository — cost if wrong: a non-`node` host whose command line must be matched is captured again.
- Ruling: Task 1 is the hold reader, not the wiring — the Approach keeps risk 2 open until the first task — cost if wrong: the end-to-end proof comes one task later.
- Ruling: two sessions are the same when their markers are equal, or when their pid and start time are equal — a session is then never refused by its own hold, whether or not the marker survives a resume, a compaction, or a subagent — cost if wrong: a new marker in one claude process (after `/clear`) counts as the same session.
- Ruling: a hold is judged only when `CLAUDE_PID` appears among the command's parent processes; otherwise exit 2 — fails closed against a partial process table (plan critique 1.7) — cost if wrong: a sandboxed command cannot continue until it runs outside the sandbox.
- Ruling: `CLAUDECODE=1` without both `CLAUDE_CODE_SESSION_ID` and `CLAUDE_PID` exits 2 and asks for a newer Claude Code — in Claude Code the hold is promised (D-17) — cost if wrong: anyone on an older Claude Code is blocked.
- Ruling: `worktree clean` run from another tool trusts the process table as it reads it — there is no reference process to check it against — cost if wrong: a holder hidden by a partial table is read as dead.
- Ruling: Continue is `accord worktree open <id> --continue`, and the skill tells its two refusals apart by their first words `not a ticket:` and `not claimed:` — as the distinct-first-line Ruling — cost if wrong: one option to rename.
- Ruling: the Continue lookup (D-18) reads only refs already in the clone and fetches nothing — D-12 — cost if wrong: a teammate's branch not yet fetched is taken as a New request until a bare `/accord` fetches.
- Ruling: the session-probe Ruling no longer applies; the probe and its fixtures are dropped after D-17 — cost if wrong: none.
- Ruling: Pick up claims only a ticket whose file is on the default ref (`git cat-file -e`) as well as in the checkout — the worktree is built from that ref, so a claim with no ticket file would follow (plan critique 2.1) — cost if wrong: a ticket that exists only in the checkout must merge to main before Pick up.
- Ruling: `worktrees(root)` runs `git worktree prune` when an entry is `prunable` — it drops only git's records of missing folders; branches and locked worktrees are untouched (plan critique 2.2) — cost if wrong: a worktree folder moved by hand can no longer be reattached with `git worktree repair`.
- Ruling: the intro paragraph of the `accord` SKILL.md is deleted to fit the 5,120-byte limit — the frontmatter `description` says the same (plan critique 2.4) — cost if wrong: a reader loses one orienting sentence.
- Ruling: in `ids.md`, the `## Dropping instead of renaming` steps get no `--worktree` — a replacement ticket is made inside the dropped ticket's own session — cost if wrong: a lane M replacement ticket is written in that session's checkout.
