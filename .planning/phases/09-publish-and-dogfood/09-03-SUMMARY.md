# Phase 09 Plan 03: Generated npm README Summary

`packages/cli/README.md` is now generated from the root README by `packages/cli/scripts/gen-readme.mjs`,
wired third into `npm run gen`, and guarded by a three-case drift/LF/banner test — so the published npm
page exists (D-156 defect 1) and cannot silently fall behind the README anyone actually reads.

## Tasks

### Task 1: Generate `packages/cli/README.md` from the root README

`packages/cli/scripts/gen-readme.mjs`, 14 lines, modelled on `packages/core/scripts/gen-templates.mjs`:
first-line comment naming source, output, decision and why Node built-ins are legal outside `src/`;
`fileURLToPath(new URL('../', import.meta.url))` for the package root; `.replace(/^\uFEFF/, '')
.replace(/\r\n/g, '\n')`; a one-line receipt. The output is a plain `.md`, so no `JSON.stringify` and no
`as const` — the "Do not edit" banner is an HTML comment on line 1 followed by a blank line.

The root README ends with exactly one `\n` (`tail -c 20 README.md | od -c` → `M I T \n`), so a verbatim
copy satisfies "exactly one trailing newline" with no trimming. No trimming was added.

` && node packages/cli/scripts/gen-readme.mjs` appended to the root `gen` script; the existing two
commands and the `&&` style are unchanged.

### Task 2 (TDD): The drift test

`packages/cli/test/readme.test.ts`, three cases copied from `templates.test.ts`'s `describe('generated
module')`: drift (message `packages/cli/README.md drifted: run npm run gen`), LF + no BOM, and the banner
line naming `gen-readme.mjs`. `const BOM = String.fromCharCode(0xfeff)` and the same `normalise` helper.
`normalise` is applied to the **re-derived input only**; the generated file is read as-is.

**RED→GREEN observed, not asserted.** `packages/cli/README.md` was perturbed with a single appended `x`
before the test file was written. First run:

`npm run gen` restored the file byte-for-byte and the same run went green — `Tests  3 passed (3)`. This

## Deviations from Plan

**1. [Rule 3 — blocking] `\uFEFF` written to disk as a literal BOM byte**

- **Found during:** Task 1, at the first `npm run lint`.
- **Issue:** the file-writing tool emitted the escape `\uFEFF` as the literal three-byte BOM
  `EF BB BF` inside the regex literal. `npm run lint` went red:
  `12:71 error Irregular whitespace not allowed no-irregular-whitespace`. Left unfixed the generator
  would still have worked — a literal BOM in `/^<BOM>/` matches a BOM — but the repo's lint gate refuses
  it, and the source would have been unreadable.
- **Fix:** rewrote line 12 through a `node -e` string replace so the file carries the eight ASCII
  characters `/^\uFEFF/`. Verified two ways: `od -c` shows `F E F F` as separate bytes, and
  `('\uFEFF# hi').replace(/^\uFEFF/,'') === '# hi'` is `true`.
- **Files modified:** `packages/cli/scripts/gen-readme.mjs`
- **Commit:** none — see below.

**2. No commits, by standing instruction**

The executing instruction for this plan forbids `git commit`, per the author's global rule and the
project's solo-no-PR convention. Task 1's action line ("commit the generated `packages/cli/README.md`")
and the workflow's per-task and final commits were therefore not run. `git rev-parse HEAD` is
`2a5040af51e33ee7cfe7db5c5a56024326ff8959` at both the start and the end of this plan.

Two acceptance checks are consequently unprovable as literally written, and neither is a defect:

- *"`git ls-files -- packages/cli/README.md` is non-empty"* — the file is untracked because it has never
  been committed. The property that matters was proved instead: `git check-ignore -v
  packages/cli/README.md` exits 1, so nothing in `.gitignore` excludes it and it will be tracked by the
  commit the author makes.
- *"`npm run gen && test -z "$(git status --porcelain packages/cli/README.md)"`"* — porcelain prints
  `?? packages/cli/README.md`, again because it is untracked, not because it drifted. Byte-reproducibility
  was proved directly: perturb → `npm run gen` → identical bytes and a green drift test.

## Open point for the 09-08 dogfood ticket

**Repo-relative links in the generated README.** Per the plan, link rewriting is out of scope here and is
a D-156 ticket decision. The root README's line 7 links `[docs/design.md](docs/design.md)`, which resolves
on GitHub and 404s on npmjs.com. The generated file copies it verbatim. The dogfood ticket should rule in
its `## Plan` between (a) the generator rewriting repo-relative links to absolute
`https://github.com/<owner>/accord/blob/main/...` URLs, (b) the README avoiding repo-relative links
altogether, or (c) accepting the 404. That same line also carries D-156 defect 3
(*"**Status: design phase.** Nothing is published yet."*), so one edit can settle both.

No other surface is affected: the generated README carries no denied name — a scan of the root README
with the `DENIED` list from `test/helpers/denied.ts` returns nothing, and the generated file is a copy of
it.
