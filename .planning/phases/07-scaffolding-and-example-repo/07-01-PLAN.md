<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `cwd` → repo root | `repoRoot` resolves a git top-level from the shell's working directory; every write is composed under it |
| core → filesystem | `initFiles` returns path strings that the CLI turns into real writes without further checking |
| filesystem → write target | a path component may be a symlink or a Windows junction pointing outside the repository |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Tampering | `initFiles` path composition | medium | mitigate | Every path is a source literal; no argument and no config value becomes a path component (the `targets.ts` T-06-01 rule). `initFiles` takes only `{ name, version }` and neither reaches a path. Asserted by the "no `..` segment, no absolute path" case in Task 3. |
| T-07-02 | Tampering | `init` write loop | high | mitigate | `assertNoLink(ctx.root, path)` walks every component of every target before the first byte, exactly as `skills sync` does, and refuses with exit 2. Reusing the moved `guard.ts` export rather than a second copy is the mitigation — a second walk is a second thing to get wrong. |
| T-07-03 | Tampering | existing files in the user's repository | high | mitigate | D-130: a path that exists is skipped with no read and no write. There is no code path in `init` that calls `writeFileSync` on a path `lstatSync` found, and the CLI test asserts byte-identity across a second run and across a hand-written sentinel file. |
| T-07-04 | Information disclosure | printed paths | low | accept | `init` prints only repo-relative forward-slash literals it composed itself; no user string is echoed. The D-51 backslash assertion covers the rendering. |
| T-07-05 | Denial of service | `init` in a huge repository | low | accept | The write set is a fixed list of source literals; it does not scale with repository size. |
| T-07-SC | Tampering | npm/pip/cargo installs | n/a | accept | This plan adds no dependency. `package.json` is unmodified; no package-legitimacy checkpoint is owed. |
</threat_model>
