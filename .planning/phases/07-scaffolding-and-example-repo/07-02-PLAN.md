<surfaced_assumptions>
- **A-05 — "templates" means the two product documents, not the per-ticket ones.** `packages/core/templates/`
  holds seven files. Five (`ticket-build.md`, `ticket-maintain.md`, `epic.md`, `verification.md`,
  `prototype-header.html`) carry a `TICKET-ID` placeholder and are rendered per ticket by `accord new ticket`
  or copied by hand into `accord/tickets/<id>/`; writing them at a fixed path would put an unusable
  placeholder document in the repository. Two (`glossary.md`, `business-rules.md`) have fixed homes in the
  folder convention — `accord/product/glossary.md` and `accord/product/business-rules.md`
  (`docs/design.md` §2) — and are exactly what `ba/setup.md` steps 1 and 2 tell a BA to fill in. Those two
  are what `init` writes.
  *Alternative:* also write `accord/assets/prototype-header.html` as a template a designer copies. That is
  the case `packages/core/test/skills.test.ts` anticipates in the `REPO_ONLY` comment — if it is taken, the
  `prototype-header.html` literal comes off that list **in the same change**, never before. Not taken here:
  the header is per-ticket text with a `TICKET-ID` placeholder, so a copy at a shared path is a copy nobody
  can use unedited.

- **A-06 — an unreadable or mis-pinned `config.yml` is exit 2, not a skipped line.** D-133 fixes "exit 0
  either way" for the created-versus-skipped report; it does not speak to a repository whose config cannot
  be read. `skills()` already throws `UsageError` in that case (`skills.ts:110-112`), and D-95 makes the pin
  a hard refusal on every repository-reading command. `init` becomes repository-reading the moment a config
  exists, so it refuses the same way.
  *Alternative:* report the skill copies as skipped and exit 0, leaving a mis-pinned repository half-set-up
  with no signal.

- **A-07 — the read-back is a full `loadFromFs` + `loadSnapshot`, not a bespoke YAML parse.** One config
  parser, one schema application. The cost is that `loadFromFs` reads every file under `accord/`, which on a
  fresh repository is three files.
  *Alternative:* parse `accord/config.yml` alone in the CLI, duplicating the schema application.
</surfaced_assumptions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user's `config.yml` → `skillTargets` | a human-owned document decides which directories receive skill copies |
| filesystem → skill write target | `.claude/skills/accord-*` may be a symlink or Windows junction |
| stale CLI version → user's repository | an `npx` cache may run an older CLI against a newer contract |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-06 | Tampering | `skillTargets(config)` target directories | medium | mitigate | The runtime-to-directory table is a source literal in `targets.ts:17-22`; no config string becomes a path component (T-06-01). `init` calls the same function and adds no path input of its own. |
| T-07-07 | Tampering | skill write targets | high | mitigate | `assertNoLink` runs over every skill target before the first skill byte, reusing the moved `guard.ts` export. Asserted indirectly by the unchanged `skills-sync.test.ts` link cases. |
| T-07-08 | Spoofing | a stale CLI writing a newer contract | high | mitigate | The pin check runs against the config read back off disk, refusing with exit 2 before `skillTargets` is called. A test asserts no skill directory exists after the refusal. |
| T-07-09 | Elevation of privilege | `overwrote local edits` on a human-edited skill copy | medium | accept | Deliberate and pre-existing: D-112 makes overwriting the stated contract of the file itself, the report says so, and git is a hard precondition. `init` inherits it unchanged rather than adding a second rule (D-131). |
| T-07-10 | Information disclosure | `loadFromFs` reading the whole `accord/` tree | low | accept | Reads only files the caller already owns and prints none of them; the snapshot is used for `config` alone. |
| T-07-SC | Tampering | npm/pip/cargo installs | n/a | accept | This plan adds no dependency. No package-legitimacy checkpoint is owed. |
