## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| example content → the gates | the example is data the gate engine parses, including Gherkin, YAML frontmatter, and an HTML prototype |
| CI sandbox → the runner | the `examples` job creates a git repository and runs the built CLI inside it |
| example ticket text → a reader who copies it | the examples are the pattern teams will imitate |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-26 | Tampering | the sha substitution in the CI job | medium | mitigate | The substitution replaces one fixed literal with the output of `git rev-parse --short HEAD`, which is hex by construction; it runs inside a `mktemp -d` copy and never against the checked-out repository. The example paths are enumerated from `examples/*/` and quoted at every use. |
| T-07-27 | Tampering | the CI job writing into the checkout | medium | mitigate | Every write happens in the temp copy, and a `git status --porcelain examples` gate after a local run of the script is one of this task's `<verify>` commands rather than a note in the summary. |
| T-07-28 | Elevation of privilege | example prototype HTML | low | accept | The prototype is text the gate reads and a reviewer opens locally; nothing in this repository executes it and no CI step renders it. An asserted criterion keeps it script-free. |
| T-07-36 | Spoofing | a maintain example that passes by avoiding what it demonstrates | high | mitigate | A-28 forbids weakening the example to reach a verdict, and the summary must record every rule id that fired — an example that passed by dropping `ui: true` or the prototype would show an empty transcript, which is visible. |
| T-07-SC | Tampering | npm/pip/cargo installs | n/a | accept | This plan adds no dependency. The CI job runs `npm ci` against the committed lockfile, which the existing `check` job already does. |
