<finding_before_execution>
**The premise of G-2's second half does not hold. Measured, not argued.**

06-VERIFICATION.md states that `packages/core/src/gate/done.ts` never checks the
evidence block for emptiness, "so `accord gate done` passes with the reviewer's work
silently dropped", and the dispatch authorised widening this plan into Phase 4 code to
add such a check.

The read of `done.ts` is correct as far as it goes — `evidenceTags()` at `:32`, the
union check at `:80` and the fail/blocked map at `:104` do not look at the evidence
text. But the Done gate's Human layer does not live in `done.ts`. It lives in
`packages/core/src/gate/refs.ts`, and both files feed the one `DONE_RULES` table in
`packages/core/src/gate/rules.ts`. `evidenceUnresolved` (`refs.ts:146`) is registered
at `rules.ts:81` at level `error` and fires on any block whose evidence cites nothing
that resolves. Empty text cites nothing. Its own doc comment already says so: "An
empty block cites nothing and fails the same way."

Run against the `gate-done` PASS ticket with its `verification.md` replaced, `gateDone`
returns:

| `verification.md` shape | verdict | findings |
|---|---|---|
| as shipped, labels at column 0 | `pass` | one `gate.author-skipped` warning |
| both labels behind a list marker | **`fail`** | 2x `gate.evidence-unresolved` (error), 2x `load.result-invalid` (error) |
| `Result:` at column 0, `Evidence:` behind a list marker | **`fail`** | 2x `gate.evidence-unresolved` (error) |
| `Evidence:` at column 0 with no text after it | **`fail`** | 2x `gate.evidence-unresolved` (error) |

`gate done` is not silent on any of them. The reviewer's work is dropped by the
PARSER, which is real and is what Task 1 fixes — but the gate refuses, loudly, with a
named rule and an error level.

So this plan does not change `packages/core/src/gate/done.ts`, and adds no rule. Adding
one would put a second error finding on a defect that already has one, move every
`gate done` golden, and enlarge the `DONE_RULES` table for no behaviour change. The
project's standing rule is that a behaviour discovered to be correct during an audit is
a finding, not a licence to edit production code.

What is genuinely missing is the test. The `EVIDENCE` fixture's `@ac-1` carries
non-empty prose that resolves to nothing, so the EMPTY case — the one the SKILL-09
`empty` probe asks about — is asserted nowhere. Task 3 delivers exactly that, and
nothing else.

**For the owner:** if a distinct rule for empty evidence is still wanted for its own
sake — a clearer reason string than "cites no file, test, or command that exists" —
that is a separate, additive change to `DONE_RULES` and can be planned on its own. It
is not needed to close G-2.
</finding_before_execution>
