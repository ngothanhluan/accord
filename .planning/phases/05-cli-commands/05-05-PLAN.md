  <action>
Create packages/cli/src/commands/new-ticket.ts exporting
`newTicket(ctx: CommandContext, id: string, options: { type: 'epic' | 'story' | 'bug' }): number`.
Header comment cites CLI-04 and D-104.

Validate the id first, against the same pattern the ticket schema declares for its id property —
a leading alphanumeric followed by alphanumerics, dots, hyphens, and underscores. On a mismatch
throw `UsageError` naming the offending id and the allowed shape. This is the only guard between
a command-line argument and a filesystem write, so it runs before anything else touches a path.

Select the template from the `templates` record exported by the core public API — never read
packages/core/templates/*.md from disk, which is not shipped to a consumer's node_modules the way
the generated module is. `epic` selects the epic template; `story` and `bug` select the ticket
template named for `ctx.snapshot.config?.profile ?? 'build'`, the same defaulting idiom lint and
the gates already use.

Produce the text in two steps and no more: replace every occurrence of the id placeholder token
with the supplied id (it appears both in the frontmatter id value and on the Gherkin Feature
line, so one global replace covers both), then `setFrontmatterKey(text, 'type', options.type)`,
which preserves the trailing guidance comment on that line — that round-trip is exactly what
D-43 and D-45 bought. Change nothing else. Every other line stays the template's placeholder text
for the BA to fill; the tag scaffolding ROADMAP criterion 1 asks for is already in the build and
maintain templates, so nothing is generated.

Compute the relative path as `accord/tickets/<id>.md` with forward slashes, join it to `ctx.root`
for the filesystem call, and refuse when it already exists: throw `UsageError` naming the
relative path. Create the containing directory with a recursive mkdir when it is absent. Write
the file, print the relative path to `ctx.stdout`, and return 0.

Register the command in packages/cli/src/run.ts as a `new` command group carrying one
subcommand, `ticket <id>`, with exactly one option: `--type` limited to the three values, default
`story`. Add no other option — `--title` was rejected under D-104 — and do not add a `feature`
subcommand: the one in docs/design.md section 7 died with the features folder.

The `ticket` subcommand's action obtains its `CommandContext` by calling the shared `preflight`
from packages/cli/src/run.ts — the same single call the lint and gate actions make, not a
context assembled locally. This is what makes D-95 true rather than incidental: `new ticket` is
explicitly *not* exempt from the version pin, because the ticket template changes between
versions, and scaffolding from a template the repository is not pinned to is exactly the split
that PITFALLS section 11 describes. The pin therefore stops this command before any path is
constructed and before any byte is written, and the behavior block asserts that.
