## Decisions Made

- **No `skills/hash.ts`, no `skills/index.ts`.** `contentHash` lives in `render.ts` and the exports go straight out of `packages/core/src/index.ts`. Both files would have exactly one caller. The plan sanctioned this deviation from 06-PATTERNS.md explicitly; the analog discipline still applied to the *content* (FNV-1a constants, the `fnv1a64:` prefix, and the header comment explaining why `node:crypto` is absent all copied from `gate/hash.ts`).
- **"Exactly one marker" is asserted through the exported helpers only** — `markerHash(text)` defined and `markerHash(withoutMarker(text))` undefined. A second marker regex in the test file would be the very drift this phase exists to remove.
- **`withoutMarker` consumes the marker's trailing newline**, so it reproduces byte-for-byte the string `contentHash` was given at render time. Without that the recompute would differ by one `\n` and every file would report `overwrote local edits` forever.
- **T-06-03 uses a junction on both legs.** Node ignores the `type` argument on POSIX, so `symlinkSync(decoy, dest, 'junction')` is one code path: a junction on Windows (no elevation needed) and a plain symlink elsewhere. A file symlink would have needed Developer Mode on Windows.
- **The T-06-03 case pins the exact refusal message.** Removing the `lstat` guard still exits 2 — on an `EISDIR` — so exit code alone would not have failed. Verified by mutation: with the guard removed the case fails with `expected 'EISDIR: illegal operation on a direct…' to be '.claude/skills/accord-designer/SKILL.md is not a regular file - nothing was written'`.
- **`Shortcut` is deliberately absent from the deny list.** It is ordinary English and would flag prose like "a shortcut past the gate". The tracker risk it stands for is carried by `Jira` and `Linear`. Recorded in a comment at the constant.
- **`skillTargets()` skips a role with no definition.** A roster naming `ba` and `dev` — which the shared `valid-build` fixture and `config.schema.json` both require — renders nothing for them rather than throwing, so this plan can ship one role without stubbing the other two.
- **The designer workflow names no design tool.** `docs/design.md` §5 says "a Figma link"; the shipped text says "a design link", because the "No other tools named" constraint binds skill prose and the deny list now enforces it.

**1. [Rule 3 - Blocking] A literal BOM character reached `gen-skills.mjs` and failed `no-irregular-whitespace`**

- **Found during:** Task 1 (codegen script)

- **Fix:** Replaced the literal character with the six-character escape, so the file now matches `gen-templates.mjs:10` byte-for-byte in that expression.
- **Files modified:** `packages/core/scripts/gen-skills.mjs`
- **Verification:** `npm run lint` clean; `sed -n '18p'` shows `/^\uFEFF/`; `npm run gen` still idempotent.

## Findings / decisions needing owner confirmation

1. **The `120` line ceiling (D-129) is unexercised so far.** The rendered designer `SKILL.md` is 44 lines. D-129 leaves the number to the planner and the plan proposed 120; the constant `MAX_SKILL_LINES` in `packages/core/test/skills.test.ts` carries it with a comment naming the spec's own 500-line outer bound. Plans 06-02 and 06-04 author the `ba` and `dev` workflows, which are the ones that will actually press against it. If either lands over 120, the choice is raise the number or split into a bundled reference — an editorial call, not a mechanical one.

2. **The deny list is a judgement, not a derivation.** It holds `GSD`, `BMad`, `Jira`, `Linear`, `Figma`, `Anthropic`, `OpenAI`, and `Claude Code`, built from a survey of the names this repository's own `.planning/` prose mentions. `Shortcut` was left out because it is ordinary English (see Decisions). The four runtime names and `accord` itself are deliberately allowed. If the owner wants a different boundary — e.g. banning every vendor name outright — the constant is one edit in `packages/core/test/skills.test.ts`.

3. **`prototype.md` tells the reader to start from `prototype-header.html` without saying where to find it.** No CLI command scaffolds it today (`accord new` writes tickets only), and `packages/core/templates/` ships inside the package but is not reachable by a documented path. The prose names the file as the starting point, which is what the plan asked for, but a reader in a fresh repository has no command to get it. Candidate resolutions, all out of this plan's scope: Phase 7's `init` copies it, or a later plan adds `accord new prototype <id>`. Flagged rather than invented.

4. **A roster naming a role with no authored definition silently renders nothing.** `config.schema.json` *requires* `roles` to contain `ba` and `dev`, so every valid config in existence today names two roles whose workflows do not exist yet — `skills sync` therefore writes only `accord-designer/`. This is correct for this plan and disappears when 06-02 and 06-04 land, but it means there is no signal, today, distinguishing "this role has no definition yet" from "this role's definition went missing". If that distinction should be reported once all three exist, it belongs in 06-03 beside the D-113 orphan report.
