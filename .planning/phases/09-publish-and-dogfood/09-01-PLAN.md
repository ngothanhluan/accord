<objective>
Make the one package accord publishes actually installable, and prove it by installing it.

`packages/cli/package.json` declares `@accord-dev/accord-core` under `dependencies`. D-150 makes
core `private: true`, so that package will never exist on the registry — and bundling removes the
*import*, not the *declaration*. Published as it stands, every `npx --yes @accord-dev/accord@0.1.0`
404s at install, including the smoke job that is ROADMAP criterion 1's own proof and the `npx`
invocations inside every generated `accord.yml`. D-164 moves the declaration to `devDependencies`
in the same change.

Purpose: this is the phase's tracer. It is the only slice that runs the whole path a user's install
takes — manifest → bundle → tarball → install resolution → a running binary — and it is the one
whose mistake cannot be corrected afterwards, because a published version can be deprecated and
never replaced. Everything downstream expands from a proven slice.

Output: a manifest pair, a build config, and two guards, all green, plus a local tarball install
that resolves with no registry 404.

**Wave 1 build ownership.** This plan is the only one in Wave 1 that runs `npm run build`, packs a
tarball, or runs a test that reads `packages/core/dist/` or `packages/cli/dist/` — 09-02, 09-03 and
09-04 were narrowed so they build nothing. Two concurrent builds writing the same `dist/` produce a
torn bundle and a red nobody can attribute, and `dist/` is gitignored so the wave guard cannot catch
it. If a future edit adds a build step to any other Wave 1 plan, that plan has to leave the wave.
</objective>

  <context>

    published later in this phase:

    1. **D-150** — `@accord-dev/accord-core` becomes `private: true` and is never published. The
