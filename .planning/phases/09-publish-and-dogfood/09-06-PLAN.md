<objective>
Publish `0.1.0` from a tag, over OIDC, with no secret — and record the evidence that it happened
that way, because no test in this repository can.

D-157 fixes the order for the whole phase: **publish `0.1.0` → run the ticket → publish `0.1.1`**.
npm renders the README as of publish time, so `0.1.0`'s page will be stale — the README still
describes a team contract and a component removed under D-117. That is accepted rather than
avoided: fixing the README first turns it into ordinary work and leaves the phase without a dogfood
ticket, and running the ticket against a local build is ruled out by PROJECT.md. Two benefits fall
out — the tag→OIDC path is proved twice rather than once, and the `0.1.1` bump walks the D-94 pin
through a real version change.

Purpose: this is ROADMAP criterion 1, and it is the point at which the package becomes real for
everyone else. `09-VALIDATION.md` names two of its rows as things **no test can prove** — that OIDC
succeeded, and that `npx` works on a clean machine. Both are evidenced here or the phase cannot
close.

Output: a published version, a git tag, and three filled sections in `09-VERIFICATION.md`.
</objective>

       remainder to `packages/cli/package.json` byte for byte, with no semver tolerance.
    2. Watch the run: `gh run watch` on the `publish` workflow, or the Actions tab.
    3. Capture, because Task 4 needs all of it and none of it is reproducible later:
       - the Actions run URL
       - the publish step's log, specifically the lines showing the OIDC exchange and that **no

       manifest disagree — delete the tag, fix, re-tag. A failure at `npm publish` with an auth

       check it against what was recorded in `09-VERIFICATION.md` in 09-05. A failure in the smoke
       job after a successful publish is **not** a reason to re-publish — the version is on the
       registry; re-run the smoke job.

| Boundary | Description |
|----------|-------------|
| a git tag → an unrecallable publish | Pushing `v0.1.0` starts a job that writes to a public registry. |

| the registry → every future `npx` invocation | Whatever lands here is what every user, and every generated `accord.yml`, executes. |
