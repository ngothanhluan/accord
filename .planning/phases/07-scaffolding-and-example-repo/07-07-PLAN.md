<surfaced_assumptions>
**Read these before implementing. Each is a choice the checker's required property left open; the
alternative is named so the owner can overrule without re-deriving.**

- **A-24 — the two accord invocations are intercepted by a stub named `npx`, first on `PATH`.** The
  script's pinned invocation is `npx --yes <name>@<version>`; running it for real would download the
  CLI from the registry on every test run, need the network, and take seconds. The alternative —
  rewriting `npx --yes <name>@<version>` to `node dist/cli.js` in the script text before running it —
  means the thing under test is no longer the thing shipped, and the substitution itself would become
  the untested part. A stub keeps the script byte-identical and makes the assertions sharper: the test
  can then assert exactly which invocations were made, in which order, with which arguments — which is
  what "the job reports a result" actually means.
  *Alternative:* substitute the invocation and assert only the exit code.

- **A-25 — `bash` is resolved from `process.env.ACCORD_BASH ?? 'bash'`, and its absence skips the
  suite while a guard case asserts it is never skipped on a POSIX host.** The script is bash; running
  it needs bash. On this project's Windows development machine Git Bash supplies it, but a Windows
  host whose `PATH` resolves `bash` to the WSL shim would see a different filesystem and fail for an
  environmental reason. One env override is the calibration knob for that; the POSIX guard case is
  what stops the skip from quietly swallowing the whole suite on the `ubuntu-latest` CI leg.
  *Alternative:* `skipIf(process.platform === 'win32')`, which means the author who wrote the script
  never runs it locally — the same failure this plan exists to fix, one level up.

- **A-26 — the test lives in the CLI package, not core.** It spawns a process and drives a git
  sandbox, which is what `packages/cli/test/helpers/repo.ts` already exists for (`gitIn`'s
  outside-the-sandbox refusal, `commitAll`'s per-invocation identity and `commit.gpgsign=false`,
  `cleanup`'s Windows retry loop). Core's test tree has no sandbox helper and no precedent for
  spawning anything.
  *Alternative:* core, re-creating three helpers that already exist one package over.

- **A-27 — four diff shapes, not three.** The checker's property names docs-only, ticket-adding, and
  ticket-deleting. A fourth — a gate that fails — is added because the `code` accumulator is a branch
  whose whole purpose is to survive a failure, and A-10 in 07-03 chose it over `set -e` deliberately.
  Three cases would leave the one thing that choice bought untested.
</surfaced_assumptions>

`@accord-dev/accord-core`, take the entry whose `path` is `.github/workflows/accord.yml`, `parse` it with
`yaml` (no options — the 07-03 core test settled that the default core schema is what keeps the top-level
`on` key a string), and return the `run` value of the single step that carries one. Assert there is exactly
one such step while extracting it, so a future split into two `run:` steps fails here loudly rather than
silently testing half the script. Write the script to `<sandbox>/script.sh` and run that file — do not pass
it through `bash -c`, because the script's own quoting is part of what is under test.

**Intercepting the CLI.** Write an executable stub at `<sandbox>/bin/npx`:

- first line a `#!/bin/sh` shebang;
- a line appending `"$@"` to the file named by an environment variable the test sets;
- an exit whose code is chosen by an environment variable the test sets per invocation shape — read the
  last argument, and exit 1 when it matches the shape the case wants to fail, else 0.

`chmodSync(stub, 0o755)`. Prepend `<sandbox>/bin` to `PATH` with `path.delimiter` when invoking. This is why
the script runs verbatim: the test changes the environment, never the text.

**Running it.** `execFileSync(BASH, [scriptFile], { cwd: repo, encoding: 'utf8', env: { ...process.env, PATH: stubBin + delimiter + process.env.PATH, BASE: base, ... } })` inside a `try`/`catch` — `execFileSync`
throws on a non-zero exit and the thrown error carries `status` and `stdout`, which is how the non-zero
cases read their exit code. Resolve `BASH` once at module level from `process.env.ACCORD_BASH ?? 'bash'`,
probing it with a trivial invocation in a `try`/`catch`; when the probe throws, set a module-level
`noBash` flag and use `describe.skipIf(noBash)`. Keep the POSIX guard case OUTSIDE the skipped describe, so
it runs and fails on a POSIX host where bash did not resolve.

sandbox is the guard that keeps a missing `cwd` from touching the author's working tree, and a direct call
bypasses it. If the helper does not already export a bare `git(repo)` accessor, add one that returns the
same guarded closure rather than duplicating the guard.

Read the nothing-to-gate line out of the script text with a regular expression rather than re-typing it, so
a reworded line in `workflow.ts` does not need a matching edit here — the claim is "the script prints the
line it carries", not "the script prints this exact sentence", which 07-03's shape test already pins.

Every sandbox goes into the `repos: string[]` + `afterEach` collection, so a failing assertion still cleans
