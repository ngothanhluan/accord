<planning_notes>
**Flagged decisions surfaced by this plan — the developer should confirm or overrule them.**

1. **The empty-cell glyph.** D-91 and D-100 write the empty cell as an em dash. PITFALLS section
   12 and the CONTEXT discretion note require ASCII-only table output, and an em dash is outside
   ASCII — legacy `cmd.exe` code pages render it as garbage in the same way a box-drawing
   character does. This plan renders the empty cell as the ASCII hyphen and keeps the machine
   value as the data word (`none`), honouring the intent of D-91 and D-100 (a visible marker
   that distinguishes "nothing recorded" from "zero") while satisfying the character-set
   constraint. It is one exported constant in packages/cli/src/render/table.ts, so reversing it
   is a one-line change.

2. **The exit code of `status`.** The CONTEXT does not state one. This plan exits 0 whenever the
   table or the JSON array is printed, on the reasoning that D-91 makes a row a trace rather
   than a verdict — only the pin check and other usage errors exit 2. A `status` that exited 1
   because some ticket has a lint error would make the daily screen unusable in CI scripts.

3. **Terminal width.** Discretionary per the CONTEXT. This plan reads no terminal dimension: the
   column budgets are constants, so the output is byte-identical on every host and can be pinned
   by a golden. A narrow terminal wraps, which is the shell's job.
</planning_notes>

Create packages/cli/src/render/table.ts exporting `EMPTY_CELL` and
`renderRows(rows: StatusRow[], trackerCells?: Record<string, string>): string`. It is pure:
no stream, no colour, no terminal query, and it returns text ending in a newline — the same shape
as packages/core/src/lint/render.ts, which is its structural analog even though the content
differs.

Columns, in this order: `id`, `type`, `status`, `parent`, `ui`, `err/warn`, `ready`, `ticks`,
`tracker`. Cell rules:
- an absent optional field renders as `EMPTY_CELL`, which is the ASCII hyphen (see the flagged
  decision in the planning notes)
- `ui` renders `yes` or `no`
- `err/warn` renders the two numbers joined by a slash
- `ready` renders the data word from the row, with `none` rendered as `EMPTY_CELL`
- `ticks` renders `<ticksVerified>/<ticksTagged> <ticksBinding>`, and renders `EMPTY_CELL` when
  `ticksTagged` and `ticksVerified` are both 0 — which is what makes an epic's ticks cell empty
  without the renderer needing to know what an epic is
- `tracker` renders `trackerCells[row.id]` when that map supplies a cell, else the row's own
  tracker map flattened as `key:value` pairs joined by a single space, else `EMPTY_CELL`. The
  optional map is the seam the tracker adapter fills later; nothing else about this file changes
  when it arrives.

Before measuring or padding, sanitise every cell: replace any character that is a newline, a
carriage return, an escape, or any other C0 control with a space, collapse runs of whitespace to
one space, and trim. A cell longer than its column budget is cut to the budget minus three and
suffixed with three ASCII dots. Column budgets are module constants; read no terminal dimension,
so the output is deterministic and goldenable. Widths are computed with `padEnd` over the
measured cells (STACK Decision 5). The separator line is ASCII hyphens. No box-drawing character
appears anywhere in this file.

Create packages/cli/src/commands/status.ts exporting
`status(ctx: CommandContext, options: { json?: boolean; all?: boolean }): number`. It calls
`statusRows(ctx.snapshot)` once, filters out rows whose `status` is `archived` unless
`options.all` is set, and counts how many it removed.

The hidden count is reported on every output mode — D-93 requires that the omission is never
silent, and a machine consumer is no less entitled to know than a person. Only the channel
differs, because D-98 reserves stdout under `--json` for the core object verbatim:
- text mode: the count goes in the stdout summary line, alongside the visible count
- `--json`: the count goes out as exactly one line on `ctx.stderr`, the same channel D-100
  already uses for the tracker warning. Write that line only when the count is greater than
  zero, so a clean run leaves stderr empty.

When `options.json` is true it writes `JSON.stringify(visibleRows, null, 2)` plus a newline to
`ctx.stdout` and nothing else on that stream — an empty repository therefore produces the two
characters of an empty array, which is what a machine consumer needs (D-98). Otherwise it writes
`renderRows(visibleRows)` followed by a summary line naming the visible count and the hidden
count; when there are no rows at all it writes one explanatory line instead of an empty table.
The summary and the explanatory line go to `ctx.stdout` in text mode — they are the human
answer, not diagnostics. Return 0.

Register `status` in packages/cli/src/run.ts with the two boolean options `--json` and `--all`,
routed through the existing preflight.
