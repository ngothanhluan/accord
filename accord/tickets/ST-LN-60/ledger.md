# Ledger

## Rulings
- Ruling: a fix made for a pull request comment after verify takes the path `failure.md` already gives a failure reported after verify (a review round on the fix, then verify again), not a new path — `gate done` already fails on a commit that changes code after the verified commit (packages/core/src/gate/done.ts:218-245), so a second route would only duplicate it — cost if wrong: the owner wanted a lighter path for small comments; shown at approval
- Ruling: a lane S ticket's pull request is covered too, through the lane S branch `failure.md` already has (continue at the lane S steps; the fix gets another review round) — lane-s.md step 6 opens a pull request that waits for the owner's merge, so it can receive comments like a lane M one — cost if wrong: one sentence of scope the owner did not want
- Ruling: a question about an unclear comment goes to its author as a drafted reply in that comment's thread, under D-04's draft-then-yes, and no comment is fixed until every unclear one is answered — the comments may be related, as the queued intent says, and D-04 already covers every post to GitHub — cost if wrong: the owner wanted such questions asked to them in chat instead
- Ruling: the audit's splits are settled in the criteria text, each to the reading accord already uses — ac-1 counts a review thread, a top-level comment or a review's summary as one comment (replies belong to their thread, matching ac-5's one reply per thread), comments by bots left out since a failed check already takes `failure.md`, and "before fixing any comment" replaces "before changing any file" so the marks can be written down; ac-2 posts the questions first, as their own drafts under D-04, and the answer may come from the author in the thread or from the owner in the chat; ac-3 stops every comment, as accord's rule stops the run on anything touching a Veto, Decision or Correction; ac-4 fixes the comments as one review round (accord-review step 4 gives one brief for a round's patch findings) and one new round and one verify cover them; ac-5 takes one yes for the whole set of drafts, the owner may change any draft first, and "nothing posted" covers replies, comments and reviews, not the fix commits, which are pushed as the stage skills push them — the owner approves the rewritten text at step 9 — cost if wrong: a criterion read differently from what the owner meant, caught at approval
- Ruling: the request is routed by one sentence beside the failure sentence at the top of the accord skill, "without the session check", and `comments.md` opens the ticket's worktree itself as `failure.md` step 2 does — the session check would otherwise stop such a request in the ticket's own session as a New request, and `worktree.md` is outside `## Scope` — cost if wrong: a request typed without `/accord` in a session that never loaded the accord skill is not routed
- Ruling: a comment that reports a failure in the work (a crash, a wrong output, a failing case) follows `./failure.md` from its step 1, through `accord-debug`, like a failed check; only the other comments that hold are fixed as review findings — `failure.md` already owns "someone reports a failure in its work" after verify, and a second route would let an agent fix a bug without a root cause (review round 3, Should 1) — cost if wrong: a small bug named in a comment takes a debug episode instead of a direct fix
