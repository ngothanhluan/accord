line saying it must be uncommented before the first ticket carrying an `@test:` scenario. Chosen over
adding a lint finding, because the user should meet the key while reading the file rather than when CI
goes red, and because `07-CONTEXT.md` forbids lint-rule changes in this phase.

**State the residual plainly, because the plan does not hide it.** A commented block leaves the key
absent, so a fresh repository still fails `gate.tests-unconfigured` on its first `@test:`-tagged ticket
until a human uncomments the block and points it at a real report. That is the owner's decision, not a
scope reduction: the gap's original truth — "a repository created by `accord init` can pass the `gate done`
that the workflow `accord init` writes" — is satisfied *conditionally*, after the documented one-line
edit. What this plan must make true is that the edit is discoverable, that it is exactly one edit, and
that performing it produces a valid config. The third is asserted, not assumed.
