that removing the tracker changes nothing else.

the tracker exists.

  <action>
Create packages/cli/src/tracker/github-issues.ts. Header comment cites INTG-01, D-99, D-100,
D-101, and D-102, and states in one line that this module is read-only and that nothing depends
on it.

Export `interface IssueFacts { title: string; state: string; labels: string[] }` and
`fetchIssues(repo: string, numbers: number[], env: NodeJS.ProcessEnv, fetchImpl = fetch)` —
declare the environment parameter with that exact type, so the module's only route to the
environment is visible in its signature. The `fetchImpl` parameter exists so the
tests can drive every failure path without a network; it is the one seam in this file and it
defaults to the global `fetch` that Node 22 provides.

Token lookup, in this order and no other (D-102): `env.GITHUB_TOKEN` when it is a non-empty
string; otherwise `execFileSync('gh', ['auth', 'token'], ...)` using the same options shape as
the existing loader spawns — literal argument array, no shell, `stdio: ['ignore', 'pipe',
'pipe']` — trimmed. Any failure of that spawn, ENOENT included, means "no token": catch it,
return undefined, and never rethrow. Read the environment only from the `env` argument; this
file must not touch `process.env`.

Requests: one `GET https://api.github.com/repos/{repo}/issues/{n}` per entry in `numbers`, issued
with `Promise.all` (D-101 — no pagination, no list endpoint, and no issue fetched that nothing
references; plain Promise.all is acceptable at pilot scale). Headers: the GitHub JSON accept
header, the API-version header, and an Authorization bearer header only when a token was found.
Treat every response as untrusted input: read only `title`, `state`, and `labels[].name`, coerce
each to a string, and sanitise every extracted string before returning it — replace C0 controls
including newline, carriage return, and escape with a space, drop or transliterate anything above
code point 127 so the value is pure ASCII, collapse whitespace runs to one space, and trim. Do
not return the raw response object and do not carry unknown fields through.

Degradation (D-100): a non-ok status, a rejected fetch, or a JSON body that does not have the
expected shape omits that one number from the issues record and contributes to a single
human-readable warning string returned alongside. Never throw out of this function, never change
an exit code, and never include the token or an Authorization header value in the warning.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| environment to CLI | GITHUB_TOKEN and the output of `gh auth token` are secrets entering the process |
| CLI to child process | `gh` is spawned by name to obtain a token |
| network to CLI | GitHub REST response bodies are untrusted input rendered into a terminal |

| T-05-18 | Elevation of Privilege | packages/cli/src/tracker/github-issues.ts | high | mitigate | `gh` is spawned by name with a literal two-element argument array and no shell option, matching the existing loader's shape; covered by the spawn allowlist test from 05-01, which admits only git and gh |
