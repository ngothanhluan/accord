# Ledger

## Rulings
- Ruling (since settled by the owner as D-05): each arm runs every sample three times, and the spread D-02 compares against is the spread of those three runs — docs/specs/2026-10-12-workflow-layer-design.md "Matrix" sets three runs per cell, and D-02 needs repeated runs to see the spread — cost if wrong: about 90 scout runs for 5 samples; too few runs make a tie look wider than it is
- Ruling: the samples are the 5 round 1 scout samples plus samples from done tickets with a merged diff, so that tickets touching more than 5 existing files are covered — recall drops from 0.94 to 0.60 above 5 files (accord/research/2026-10-30-harness-architecture.md:123), and how many of the 5 round 1 tickets touch more than 5 files is not checked yet — cost if wrong: more runs; the plan fixes the count
- Ruling: the three measures of D-02 are computed by script wherever they can be (scout check exit, logged absent rows, recall against the D-03 list); a judge model is used only for a claim the script cannot decide, and judges it twice — a script gives the same score every time, which removes round 1's judge-counting noise — cost if wrong: a false "only"/"none" claim written outside the Absent table is missed if the judge brief does not ask for it
- Ruling: the approach ladder is 1. Named arm rounds on the round-1 harness: round definitions as data with a model and effort per arm, runs scored by script at the sample's commit, a cost-weighted report, cached scores, a hand-run gathering step and the round 1 fixes; 2. Option 1 plus judged prose claims: the same, plus two judges per scout run counting "only" or "none" claims written outside the Absent table; Named arm rounds on the round-1 harness is Recommended because it meets every criterion by script, as the Intent asks, the scout prompt already requires every "only" or "none" claim to be an Absent row, and the judge harness is still built and tested for the executor and planner benchmarks — kept so a resumed or revised round critiques the option ## Approach names and nobody picks again — a ruled-out option comes back
- Ruling: "passes accord scout check" means core `scoutCheck` returns no failures, given the sample worktree's tracked files and text and the sample's ticket, the same function and facts as `accord scout check --ticket`; the CLI is not run in the sample worktree because the version pin refuses it at an old base (packages/cli/src/run.ts:83-86) — cost if wrong: only the lane numbers differ, and they are not scored
- Ruling (replaced by the prose-claim Ruling below, after approach-review 1.3): a false "only"/"none" claim is an `## Absent` row whose re-run search hits outside its allowed hits, counted once per row — ac-2 says "a search contradicts" and the Intent says "by script"; the scout prompt requires such claims to be Absent rows (.claude/agents/accord-scout.md:17) — cost if wrong: a claim written in prose is missed
- Ruling: the true file list is the union, over each first-parent merge of the ticket's branch into the default branch, of the modified or deleted files (`--no-renames --diff-filter=MD`, merge base to branch tip), with nothing excluded; a ticket with no merge has no truth and is left out of the round and named in the report (scout sample 3, ST-LN-33, dropped) — D-03 read literally — cost if wrong: one fewer sample
- Ruling: gathered samples go to a new `scripts/benchmark-gathered.json`, numbered after their agent's round 1 samples; round 1's list, its 45-sample test and its modes stay unchanged — cost if wrong: a round reads two lists
- Ruling: the scout round has no judges (`judges: 0`); the judge count lives in each round definition — every scout measure is scored by script — cost if wrong: none for the scout; ST-LN-89/90 set their own count
- Ruling: round names start with `r` (for example `r2-scout`), so the compliance report keeps leaving round runs out (scripts/compliance.mjs:37) — cost if wrong: round runs counted as real work in compliance
- Ruling: the gathering task comes second in build order and ends by running `--gather` on the done tickets the scout round needs, those with a scout run and more than 5 truth files, before about 2026-11-11 — the transcript retention date — cost if wrong: samples lost to retention
- Ruling: in ac-3, "best" is the highest mean for scout check passes and wiring recall and the lowest for false claims; when several arms share the best mean on a measure, the cheapest of them is the best arm of that measure; a pass counts only when it has a run on every sample — the auditor read ac-3 three ways on these points (2026-11-02); these readings follow D-02, D-06 and D-08 — cost if wrong: a different winner when best means tie

- Ruling: false claims add contradicted prose claims (matched words; a backticked non-path token searched as an Absent row through `scoutCheck`) to contradicted Absent rows; prose claims with no token are counted and shown, not scored — ac-2 defines the measure as claims a search contradicts (approach-review 1.3) — cost if wrong: unsearchable prose claims do not lower an arm's score
- Ruling (replaced after approach-review 2.1 by the recall-on-every-sample Ruling below; the truth intersection stays): a scout round takes only samples whose brief asks for the files the change touches, and the truth is intersected with the files tracked at the sample's base — approach-review 1.5 and ac-3's "over every sample" — cost if wrong: fewer samples, or a question brief scored on recall
- Ruling: lane scouts are tied to their ticket through the same session's `scout: <id> report` commit, or named by hand — approach-review 1.6 — cost if wrong: a scout from another session is missed unless named
- Ruling: gather copies before it checks; replay failures are kept but left out of rounds — approach-review 1.2 — cost if wrong: disk space
- Ruling: `--clean` refuses while any named round state has an unscored row — approach-review 1.4 — cost if wrong: a stale state needs `--force`
- Ruling: named rounds have no `current` arm, and scoring uses one scorer per agent, only the scout's here — approach-review 1.8 — cost if wrong: ST-LN-89/90 add their scorers
- Ruling: a ticket is done when its file on the default branch has a non-empty `verified_hash`, in any lane — ac-5 needs a rule — cost if wrong: a lane S ticket without the hash cannot be gathered
- Ruling: a gathered sample's base is the last commit on the run's branch before the dispatch, from merged history — replay needs a base — cost if wrong: drift marks the sample as unable to replay
- Ruling: a round is dispatched from a session in the main checkout, so every arm runs `.claude/agents/accord-scout.md` there — round 1 dispatched the same way, and it is the definition the owner's choice applies to — cost if wrong: replies to question briefs list no files, which scout check's missing `## Files` failures in the run rows would show
- Ruling: recall is scored on every scout sample with a merge, whatever its brief asks, so round 1's samples 1, 2, 4 and 5 stay in — D-03 names the 0.94 / 0.60 measure, taken over all real scout runs (approach-review 2.1) — cost if wrong: intent-stage samples widen recall ranges and make a cheaper arm tie more easily
- Ruling: a prose claim is checked only when it names one subject and its own folders or files, and is searched only there — no search is wider than the claim (approach-review 2.2) — cost if wrong: a narrow claim false elsewhere is missed, the same for every arm
- Ruling: named rounds, `--gather` and the `--clean` guard resolve the bench root from `--git-common-dir` of the main checkout — a hand-made worktree need not be a sibling of main — cost if wrong: nothing lost, the folder is printed and can be moved
- Ruling: the owner allows 1 more approach critique rounds after round 3 of cycle 1 — "A" — one more critic and planner run (2026-11-02, option a: one more round to fix 3.1; b, accept it, and c, the judged option, not chosen)
- Ruling: a prose claim's allowed hits are every tracked file the whole reply names in backticks, and a file at the repository root adds no folder — the claim's own line leaves out the definition the reply cites on another line, and the root folder `.` searches the whole repository for a claim about one file (approach-review 3.1) — cost if wrong: a true claim still counts as false when the reply names no file holding its subject, and a claim naming only root files is shown beside the measure instead of in it
