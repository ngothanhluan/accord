<objective>
Give the `status` command its data: one pure function in core that turns a RepoSnapshot into the
flat, sorted `StatusRow[]` D-91 and D-92 describe.

Purpose: this is the whole of `status` except printing. Keeping it pure and in core means it is
covered by the existing golden harness, is reusable by the Phase 8 host without a second
implementation, and cannot accidentally acquire a filesystem or network dependency.

Output: packages/core/src/status/rows.ts, its barrel export, and golden tests over the existing
fixtures.

<planning_notes>
**Flagged assumptions surfaced by this plan (not resolved by any D-number).**
- A ticket whose frontmatter failed the schema has no `type` and no `status`. D-91 does not say
  what its row looks like. This plan omits both keys for that row and still reports its error
  count, on the reasoning that a broken ticket disappearing from `status` is the worst outcome —
  the row is how the user learns it is broken. Surfaced for the developer.
- `parent` sorting for a ticket with no parent. This plan sorts on `parent ?? ''`, which places
  every parentless ticket (epics and orphan stories) before any grouped child. D-92 fixes the
  axis but not this tie-break. Surfaced for the developer.
</planning_notes>

  <action>
Create packages/core/src/status/rows.ts. Header comment cites CLI-05, D-91, D-92, and D-93 and
states in one line that a row is a trace of what is written in the files and never a verdict.

Export `interface StatusRow` with exactly these fields, one short comment per field:
`id: string`; `type?: 'epic' | 'story' | 'bug'`; `status?: 'draft' | 'open' | 'archived'`;
`parent?: string`; `ui: boolean`; `errors: number`; `warnings: number`;
`ready: 'none' | 'ok' | 'stale'`; `ticksVerified: number`; `ticksTagged: number`;
`ticksBinding: 'none' | 'bound' | 'stale'`; `tracker?: Record<string, string>`.
The three-state columns carry data words, not display glyphs — the renderer in the CLI decides
what an empty cell looks like. Optional fields are omitted with the
`...(x === undefined ? {} : { x })` spread already used at the end of `run` in
packages/core/src/gate/index.ts, never set to undefined (D-54).

Export `statusRows(snapshot: RepoSnapshot): StatusRow[]`. It calls `lintSnapshot(snapshot)` once
for the whole repository and reuses `scoped(findings, id)` from packages/core/src/gate/index.ts
to split the counts per ticket — do not re-implement that string comparison, and do not call
`gateReady` or `gateDone` from this file at all (D-91: a real gate for N tickets is N full-repo
lints, and most in-flight tickets would render fail — accurate and useless). Compute the ready
and ticks columns from `acHash(ticket.scenarios)` and the frontmatter, exactly as the behavior
block specifies. `ticksTagged` counts scenarios whose `acTag` is defined. Return every ticket,
archived included: filtering is the caller's job (the `--all` flag and the hidden-count summary
are display concerns, D-93).

Sort with the code-point `cmp` idiom from packages/core/src/gate/index.ts:
`cmp(a.parent ?? '', b.parent ?? '') || cmp(a.id, b.id)`. Never a locale-aware compare — the
goldens must be byte-identical on every host.

Re-export `statusRows` and the `StatusRow` type from packages/core/src/index.ts following the
existing D-55 grouping and comment style. `scoped` stays private: this file is the only new
consumer and exporting it would widen the public surface for a helper whose scope semantics are
internal.
