# Ledger

## Rulings

- Ruling: the audit's split readings that today's behaviour or the owner's answers settle are settled in the criteria's wording and shown to the owner at the yes — ac-1: "default branch" is the one accord resolves today, origin/HEAD, else main, else master (packages/cli/src/load/fs.ts:574-591); ac-3 and ac-4: "verify starts" is the verify stage of /accord, which starts only when review.md ends with a verdict; ac-4: nothing is stored on a conflict and the next verify tries the merge again, since D-03 stops the work until the owner or the session resolves it; ac-5: `new ticket --worktree` goes on after a failed fetch too, per D-06 — cost if wrong: the owner rewords a criterion at the yes.
- Ruling: the second audit's split readings are settled in the criteria's wording the same way and shown at the yes — ac-1: "starts at" means cut from, since Pick up commits `claim: <id>` and `new ticket --worktree` commits the ticket file on the new branch; ac-2: the command is built from the resolved default branch, per the first ruling's ac-1; ac-3: the missing commit is not yet fetched, so verify must fetch first (D-02, D-04); ac-4: "nothing stored" means no merge commit, no merge in progress and no blocked marker, while a ledger note stays allowed since D-03 forbids none; ac-5: exactly one line of accord's own, quoting git's first error line, which is what `worktree clean` prints today with git's stderr captured (packages/cli/src/commands/worktree.ts:439-447, 481) — cost if wrong: the owner rewords a criterion at the yes.
- Ruling: how the time limit of D-08 is enforced (an accord-side timer or git's own low-speed settings) and whether `worktree clean`, which shares the fetch helper, gets it too, are left to the approach — cost if wrong: none at intent; the approach chooses.
- Ruling: whether the fetch and merge before verify are CLI code or skill text is left to the approach — the criteria state only what the owner sees — cost if wrong: none at intent; the approach chooses.
- Ruling: the D-08 limit is an accord-side `execFileSync` `timeout` of 30 000 ms on the fetch only, through one fetch helper; the figure lives in its own module so the ac-5 test can mock it the way `load/proc.js` is mocked, since vi.mock cannot swap a binding used inside the same module (critic 6) — git's low-speed settings bound neither the connect nor ssh — cost if wrong: on Windows a kill during the ref update can leave a stale ref lock that keeps later fetches failing, which D-06 turns into a repeated line, not a stop.
- Ruling: `worktree clean` keeps today's fetch with no limit, since D-06, D-08 and ac-5 name Pick up, `new ticket --worktree`, Continue and verify only (critic 7) — cost if wrong: a hanging fetch at the dashboard still hangs, as today.
- Ruling: Pick up and `new ticket --worktree` fetch before any ref or the snapshot is read, so the claimant check, the remote-branch check and the id allocation see the fetched refs (critic 1) — cost if wrong: two people claim one ticket, or a new ticket takes an id a teammate already pushed.
- Ruling: the merge before verify passes `--no-ff --no-edit --no-overwrite-ignore`, so ac-3 always gets a two-parent merge commit and an ignored local file is never overwritten; when the branch is not behind nothing is merged and nothing is printed (critic 2) — cost if wrong: an ignored file on a path main now tracks stops the merge, which the owner then moves.
- Ruling: a failed merge names the conflicted files from `git diff --name-only --diff-filter=U`, runs `git merge --abort` only when MERGE_HEAD exists, and otherwise quotes git's first error line (an untracked file in the way, a rejecting hook); every failed merge exits 2, which worktree.md maps to "show the message and stop" (critic 3) — cost if wrong: an exit code that differs from the 1 used for gate failures.
- Ruling: the merge refuses outside the ticket's own branch, on tracked uncommitted changes (`git merge --abort` may not restore them), and unless the ticket's stage is `verify`, so D-04's "merge once, after review and before verify" is held by the tool — cost if wrong: a person who wants to merge by hand earlier types `git merge` themselves.
- Ruling: with no `origin` remote the merge does nothing and exits 0, as `worktree clean` does; with no default ref it prints one line and exits 0 — cost if wrong: verify runs unmerged in a repository that has no remote.
- Ruling: after a merge that changes the pinned version in `accord/config.yml`, the merge prints the line `checkPin` already prints, so a verify stopped by the pin check says why (critic 4) — cost if wrong: none found.
- Ruling: `review-package` without `--base` after the merge lists main's merged files as undeclared; this only bites when a fix after verify goes back through review, which no criterion covers, so it goes to a follow-up ticket — cost if wrong: a reviewer after a post-verify fix sees main's files in the package.
- Ruling: an offline `/accord` can wait on two fetches (the dashboard's clean, then Pick up), the second capped at 30 s (critic 9) — cost if wrong: up to 30 s of waiting before work goes on offline.
- Ruling: the third audit's split readings are settled by the Decisions in the criteria's wording and shown at the yes — ac-3: the parents are ordered, first the ticket branch's previous head and second the default-branch commit, since D-04 merges `origin/main` into the ticket branch; ac-5: the timeout line names the limit's figure, since D-10 quotes "no answer within 30 seconds" — cost if wrong: the owner rewords a criterion at the yes.
- Ruling: Continue re-reads the snapshot after its fetch, through the same helper as Pick up — one code path — cost if wrong: one extra snapshot load per Continue.
- Ruling: a successful merge and a branch that is not behind both print nothing — no criterion asks for a confirmation line — cost if wrong: the owner's report cannot quote that a merge happened.
- Ruling: after a merge that changes the version pin, `checkPin`'s error propagates and `worktree merge` exits 2 with the merge kept — preflight checked the pin before the merge, so only the merge can change it, and every later accord command would refuse anyway — cost if wrong: verify stops on a merge that succeeded.
- Ruling: D-05's edit to ST-LN-11 is not made on this branch — PR #53 already rewrote ST-LN-11 line 33 on origin/main, and the merge before verify brings it here — cost if wrong: none; editing it here would only conflict at that merge.
