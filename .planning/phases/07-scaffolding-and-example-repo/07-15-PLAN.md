**GC-WR-03.** `packages/core/src/scaffold/init.ts:55` says "Uncomment the two lines below before the
first ticket carrying an `@test:` scenario." Following it literally is not sufficient and is ambiguous.
Not sufficient: `reports/junit.xml` is accord's invention, so until the team points `report:` at the file
their own runner writes, `lint` carries a standing `lint.report-missing` warning and `gate done` fails
with `tests.report "reports/junit.xml" is not in the snapshot` — a worse diagnostic than the absent key
gave, because a key that looks configured and is not is harder to read than one that is missing.
Ambiguous: deleting only the `#` from `# tests:` yields ` tests:`, a YAML indentation error, after which
every command answers `accord/config.yml is missing or failed its schema; run accord lint`.

**GC-WR-04.** `packages/core/test/scaffold.test.ts:144` anchors the generated side of the same assertion
on `lines.indexOf('# tests:')` and the example side on `example.split('\n').slice(28, 30)` — the fixed
offset its own comment three lines above rejects, applied to a file no assertion pins the shape of.

The two are one change: making the instruction say what it means lengthens it, which moves the block the
assertion reads. That is exactly the fragility GC-WR-04 names, so this plan reworks the instruction first
and lets the assertion fail, then re-anchors both sides.

Purpose: the generated config is the document a team meets in their first minute. An instruction that is
half of an edit sends them to CI to learn the other half.
Output: two instruction lines that name both halves of the edit, and one assertion anchored the same way
on both sides.
</objective>
