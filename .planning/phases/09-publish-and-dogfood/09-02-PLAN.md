<objective>
The workflow `accord init` writes into a user's repository checks out the wrong commit.

`actions/checkout` with no `ref:` lands on GitHub's synthetic merge commit. `gate done` binds a
tick to `git show -s --format=%H HEAD` (`packages/cli/src/load/fs.ts:76`), and a real author's
`verified_commit` names a commit on their branch — never the merge commit, which did not exist when
they wrote it. So `tickStaleCommit` and `staleReview` both fire on a workflow that is otherwise
correct. D-162 adds `ref: ${{ github.event.pull_request.head.sha }}` beside the existing
`fetch-depth: 0`.

Purpose: this is a scaffold-template change, not a gate-rule change, and it ships inside `0.1.0`.
Shipping without it means every user's generated workflow carries the defect until they re-run
`init` — and D-130 skips paths that exist, so "re-run `init`" is a no-op for anyone who already has
the file.

**Known limit, recorded here so the next reader does not re-derive it:** this fix makes the gated
tree the author's own branch head rather than a commit nobody wrote, which is the more correct
semantics and is the right change on its own merits. It does **not** on its own make a
pull-request-carried ticket pass `gate done` — see `09-08-PLAN.md` Task 1, which carries the
evidence and the decision.

Output: one `with:` key in the emitted document, one assertion pinning it, and a header paragraph
saying why.

**This plan builds nothing.** 09-01 is Wave 1's sole owner of `packages/core/dist/` and
`packages/cli/dist/`: it rebundles them and runs the tests that read them. `dist/` is gitignored,
so `files_modified` and the wave guard cannot see the overlap — this paragraph is the declaration.
Everything below runs from `src/`: vitest transpiles TypeScript, and `npm run lint` and
`npm run typecheck` write nothing (`noEmit: true` in `tsconfig.base.json`). The one check dropped for this reason is
`npm test -- --project cli workflow-script`, which spawns `packages/cli/dist/cli.js`; against a
bundle 09-01 is mid-rebuild it proves nothing anyway. It runs for real in 09-06 Task 1's
`npm run check`, on a settled tree, before any tag exists.
</objective>
